Схема-в-админке СА – это конфигурация смарт-анкеты, включающая описание ее структуры и логики расчёта (параметры, значения параметров, коэффициенты, формулы и т.п.). Схема-в-админке СА имеет как минимум 1 Версию Схема-в-админке СА.

Нумерация Версии Схема-в-админке СА состоит из 2-х блоков в формате XXX.YYY, где XXX – имя родительской Схема-в-админке СА, YYY – номер текущей Версии Схема-в-админке СА. Номер назначается в простом возрастающем порядке, количество символов желательно не ограничивать, но показывать только значимые цифры без начальных нулей.

Анкета - это совокупность калькуляций затрат на разработку конкретного модельного сервиса (в дальнейшем возможно изменение). Анкета имеет как минимум 1 Версию СА.

Версия СА - это конкретная калькуляция затрат на разработку модельного сервиса, которая может отличаться от других версий как выбранными значениями опросника, так и Схема-в-админке СА или Версией Схема-в-админке СА. То есть каждую новую Версию СА можно создавать на основе различных Схема-в-админке СА и Версий Схема-в-админке СА. Активной может быть только одна Версия СА.
Нумерация Версий СА производится по тому же принципу, что и Версий Схема-в-админке СА.

1.	Создание Версии анкеты

Первая Версия СА создается автоматически при создании новой Анкеты. Вторая и последующие Версии СА создаются из карточки Анкеты путем нажатия на кнопку «Создать новую версию». При этом:
1.	Функционал доступен для ролей с правом создания Анкет (модельные стримы).
2.	При создании каждой Версии СА сохраняется, на основе какой Версии Схема-в-админке СА она построена.
3.	Проверяется, что исходная Версия СА (для которой создают новую версию) построена на актуальной Версии Схема-в-админке СА. Если Версии Схема-в-админке СА совпадают, просто создавать новую Версию СА. Иначе выводить диалоговое окно с вопросом «Текущая Версия смарт-анкеты построена на неактуальной Версии Схема-в-админке. Использовать актуальный Схема-в-админке для создаваемой Версии анкеты?». И 2 варианта ответа: «Да», «Нет». В первом случае создавать Версию СА по актуальной Версии Схема-в-админке СА, во втором – по той Версии Схема-в-админке СА, которая сохранена в исходной Версии СА.
4.	Заполненные значения переносятся полностью из исходной Версии СА в создаваемую.
a.	Если в новой Версии СА отсутствуют какие-либо параметры, присутствующие в старой Версии СА, то их значения не переносятся. Желательно после создания новой Версии СА вывести пользователю на экран сообщение, в котором отразить подобные расхождения в составе параметров.
b.	Если в новой Версии СА отсутствуют какие-либо значения параметров, присутствующие в старой Версии СА, то для таких параметров устанавливать значения по умолчанию (как при первоначальном создании Анкеты).
c.	Если в новой Версии СА присутствуют какие-либо параметры, отсутствовавшие в старой Версии СА, то для таких параметров устанавливать значения по умолчанию.
5.	Статусы всех блоков созданной Версии СА сбрасываются на начальное значение «Создано», она становится активной и редактируемой.
6.	Исходная Версия СА становится нередактируемой как исторический срез, никаких изменений в данных не происходит, в т.ч. остаются неизменными статусы всех блоков.


Копирование Анкеты
Копирование Анкет производится в случаях, когда нужно провести калькуляцию затрат на разработку аналогичного модельного сервиса (многие значения опросника Анкеты дублируются). Копия Анкеты создаётся из карточки Анкеты путем нажатия на кнопку «Создать копию анкеты».
1.	Функционал доступен для ролей с правом создания Анкет (модельные стримы).
2.	Выводится модальное окно для ввода наименование Анкеты (как сейчас при создании – ведь мы создаем новую Анкету).
3.	Создается новая Анкета и ее первая Версия СА – со своими уникальными идентификаторами.
4.	Перенос данных и статусов в новую Анкету производится так же, как и в случае создания новой Версии СА – в т.ч. вывод вопроса об использовании актуальной Версии Схема-в-админке СА.
5.	В копируемой Анкете никаких изменений не выполняется (изменение статусов и т.п.).

2.	Завершение работы со своим блоком Анкеты
Представители стримов, участвующих в заполнении Анкеты, по факту завершения ввода данных завершают свой раздел — статус блока переходит в «Заполнено». Признак сбрасывается при изменении состава работ (типовых или нетиповых) в блоке.

3.	Утверждение Версий СА
Руководитель программ ДАДМ должен иметь возможность зафиксировать текущие актуальные Версии СА вне зависимости от их статуса готовности, без возможности дальнейшего внесения в них изменений.
1.	Функционал доступен для роли «Руководитель программ ДАДМ».
2.	В карточке Анкеты и в Реестре анкет добавить кнопку «Утвердить оценку по анкете».
3.	При нажатии на кнопку «Утвердить оценку по анкете» для выбранных Анкет (или одной Анкеты, если нажатие было в карточке):
a.	Определяется активная Версия СА, дальнейшие действия выполняются для нее.
b.	Статус Версии СА устанавливается на «Утверждена».
c.	Других изменений в данных, в т.ч. в статусах блоков не производится.
4.	Редактирование Версий СА в статусе «Утверждена» недоступно. При необходимости внесения изменений создается новая Версия СА.

4.	Изменения в Реестре анкет
1.	Отображение Анкет и Версий СА сделать аналогичной тому, как отображаются Схема-в-админкеы СА (схемы) и Версии Схема-в-админкеов (группировка Версий СА в иерархической подчиненности родительской Анкете). Версии СА (внутри иерархии) сортировать по номеру Версии СА.
2.	При нажатии на Анкету (родительскую Анкету, без раскрытия списка Версий СА) в Реестре анкет открывать активную Версию СА.
3.	Добавить на форму Реестр анкет переключатель режиме отображения Анкет:
a.	Режим «Актуальные»: выводятся активные Версии СА (утверждённые или нет). Если после утверждения новой Версии СА не создавалось — выводится утвержденная Версия СА, иначе — текущая активная.
b.	Режим «Утверждённые» (последние зафиксированные): выводятся строго утвержденные Версии СА с наибольшим порядковым номером внутри своих родительских Анкет.
К обсуждению – как это визуализировать. Если принять во внимание, что у Анкеты только 1 активная в каждый момент времени Версия СА, и своего уникального наполнения у Анкеты относительно ее Версий СА нет, то можно отображать Анкеты так: в Реестре анкет для каждой Анкеты выводить содержимое выбранной Версии СА (в зависимости от переключателя – актуальной или утвержденной). При этом должны быть доступна фильтрация по данным Анкет (т.е. эти данные должны не просто визуализироваться, но и быть «функциональными»).


5.	Сопутствующие доработки
1.	Добавить статус «Утверждена» в статусную модель Версий СА.
Действие фиксации среза в UI назвать «Утвердить оценку по анкете».
2.	Добавить команду «Утвердить оценку по анкете» в Реестр анкет (с мультивыбором). Сделать команду доступной только Руководителю программ ДАДМ.
3.	Убрать действие «Завершение заполнения анкеты» и логику, зависящую от готовности всех блоков (для ролей, отличных от Руководителя программ ДАДМ, достаточно завершения по разделам).
4.	Функционал удаления анкеты переработать по статусам:
Неутверждённые Версии СА (Черновик / В работе / Заполнено) при удалении удаляются полностью. Если удаляется последняя Версия СА, то удаляется Анкеты в целом. Утверждённые Анкеты при удалении переводятся в неактивное состояние (деактивация, срез сохраняется).
