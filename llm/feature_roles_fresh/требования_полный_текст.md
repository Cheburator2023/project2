- Функциональные требования приведены в соответствие с ТИС (последний источник правды после обсуждений с заказчиком).

# **Цель**

Описать, как роли СУМ работают в модуле Смарт-Анкета 2.0: видимость реестра и карточек, права на блоки анкеты в разрезе стримов, статусную модель заполнения, фиксацию срезов и версионирование.

Базовые группы пользователей описаны в документе[Ролевая модель СУМ, СУРМ, Смарт-анкета](https://sfera.inno.local/knowledge/pages?id=1806005) .

**Отличия V2 от V1:** конструктор шаблонов анкет, управление справочниками, жизненный цикл версий схемы, поблочное заполнение и согласование, отдельное действие «Утверждение» (фиксация среза), активация/деактивация опциональных стримов.

# **1\. Структура анкеты и модель заполнения**

Права действуют не только на анкету целиком, а на её блоки в разрезе стримов.

## **1.1. Блочная структура**

- **«Общая информация»** - общий блок (параметры инициативы и модельного сервиса); не принадлежит стриму-исполнителю.
- **«Детальная информация»** - в разрезе архитектурных компонентов (Система-источник, Объект/Витрина данных, Процесс обработки данных, Модель); формируются типовые работы, отдельно указываются нетиповые.
- **Блоки по стримам** - локальные параметры и перечни типовых и нетиповых работ каждого стрима.

## **1.2. Статусная модель**

- **Статус раздела/блока:** Создано → В работе → Заполнено. Переход в «Заполнено» - действием «Завершение раздела» (см. 3.10).
- **Статус анкеты:** Черновик → Завершено (когда все блоки «Заполнено») → Утверждена (при фиксации среза, см. 3.13).

## **1.3. Жизненный цикл**

Роль с правом создания заводит анкету; стримы дозаполняют свои блоки и завершают их; когда все блоки заполнены - анкета переходит в «Заполнено». Руководитель программ ДАДМ фиксирует срез (блокировка). Для следующего периода создаётся новая версия копированием: данные из утверждённой версии переносятся, стримы редактируют свои блоки уже в новой версии. Утверждённая версия остаётся неизменной как исторический срез.

## **1.4. Классификация стримов**

**Модельные стримы (по умолчанию, работают с модельными задачами):** KIB_SMB, PARTNERSHIPS_IT_IT, PARTNERSHIPS_IT_RND, RB, PROCESS_FINANCIAL.

**Немодельные стримы (платформенные и поддерживающие):** idsrc, mdlctl, pirm, strdat, digagt, dadm.

- **Опциональные** (активируются/деактивируются, см. 3.11): Источники данных (idsrc), Контроль моделей (mdlctl), Цифровые агенты (digagt), Потоковые данные (strdat).
- **Постоянные** (по умолчанию, без активации): ПиРМ (pirm), ДАДМ (dadm).

**Правила:** модельные задачи создают и завершают представители модельных стримов, Архитектор данных ML и Конфигуратор. Представитель стрима - не участника ЖЦМ работает только с немодельными задачами (для него используется отдельная версия схемы). Деактивация опционального стрима сворачивает его блок и исключает из расчёта итоговой оценки.

# **2\. Видимость реестра и фильтрация по стримам**

Фильтр по стриму сквозной - действует и на список анкет, и на содержимое карточки. Три уровня видимости:

- **Уровень A - только свой стрим (жёсткий фильтр):** DS, DE, ModelOps, Бизнес-партнёр стрима, Аналитик качества модельных данных стрима. Реестр и карточка - только свой стрим, внутри полная детализация. Чужие анкеты недоступны (ошибка 403).
- **Уровень B - свой + чужие, без оценок чужих стримов:** Руководитель DS/DE/ModelOps, Архитектор данных ML, Аналитик качества работы моделей ДАДМ, Аналитик качества модельных данных, Представитель стрима - не участника ЖЦМ, Валидатор, Руководитель валидации. В реестре - все анкеты (Представитель - свой стрим и анкеты, где привлечён к заполнению блока). В карточке чужого стрима - общая, детальная информация и блоки стримов, но без оценок типовых и нетиповых работ чужих стримов.
- **Уровень C - все анкеты, полная детализация:** Бизнес-партнёр, Прикладной администратор, Аудитор ИБ, Аудитор, Руководитель программ ДАДМ, Конфигуратор Смарт-Анкеты.
- **Нет доступа:** Бизнес-заказчик, Сотрудник проектного офиса.

Редактирование действует на блок своего стрима (и на общую/детальную информацию в пределах полномочий). Архитектор данных ML и Конфигуратор редактируют все блоки.

# **3\. Функциональные требования**

## **3.1 Просмотр списка анкет (реестр)**

Табличный реестр анкет с атрибутами; статусы заполнения по каждому стриму (Создано / В работе / Заполнено) и глобальный статус анкеты (Черновик / Заполнено); переход к карточке.

Состав видимых анкет определяется уровнем видимости (§2).

## **3.2 Фильтрация, сортировка и поиск по реестру**

Фильтры (по статусу, стриму, автору, дате и др.) на уровне колонки и в боковой панели; сортировка по колонкам; строка поиска. Результаты ограничены фильтром по стриму согласно роли.

## **3.3 Настройка отображения реестра (преднастройки)**

Добавление и скрытие колонок; сохранение конфигурации как преднастройки; переиспользование сохранённых преднастроек. Доступно всем ролям с доступом к реестру.

## **3.4 Экспорт анкет**

Выгрузка анкет на уровне списка; состав - по фильтру стрима. Прикладной администратор права на выгрузку не имеет (сознательное ограничение, чтобы информация не покидала подразделение).

## **3.5 Создание анкеты**

При создании предлагается структура анкеты: общая информация, детальная информация, блоки стримов.

Анкеты по модельным сервисам создают Руководитель DS, Руководитель ModelOps, Конфигуратор Смарт-Анкеты. Представитель стрима - не участника ЖЦМ создаёт только немодельные анкеты (по отдельной версии схемы с немодельными задачами).

После заполнения обязательных параметров вычисляются результирующие показатели.

## **3.6 Просмотр анкеты (карточка)**

Объём видимой информации определяется уровнем видимости (§2): уровень A - только свой стрим; уровень B - общая/детальная информация и блоки без оценок чужих стримов; уровень C - полностью.

## **3.7 Редактирование анкеты**

Логика редактирования идентична заполнению; объём зависит от роли и стрима.

Руководитель DS/DE/ModelOps, Архитектор данных ML, Конфигуратор - общая и детальная информация и блоки (Архитектор и Конфигуратор - все блоки всех стримов).

Аналитики и Представитель стрима - только блок своего стрима.

## **3.8 Удаление анкеты**

Руководитель DS и Руководитель ModelOps удаляют анкеты в рамках своего стрима; Конфигуратор - по всем стримам.

Представитель стрима - только немодельные анкеты, созданные этой ролью. Черновик удаляется полностью; заполненная анкета переводится в статус «неактивная».

## **3.9 Добавление типовых и нетиповых работ**

Типовые работы формируются автоматически по заполненным параметрам; нетиповые пользователь добавляет в блоке (задача, тип работ, оценка ч/д, коэффициент, итог) с чекбоксом «Включить в расчёт».

Оценки своего стрима - ролям этого стрима; в полном объёме по всем стримам - Бизнес-партнёр, Аудитор ИБ, Аудитор, Руководитель программ ДАДМ, Конфигуратор.

## **3.10 Завершение заполнения раздела**

Перевод статуса блока в «Заполнено» (в матрице - «Раздел»); после завершения редактирование блока блокируется. При начале заполнения статус автоматически переходит в «В работе».

## **3.11 Активация / деактивация опциональных стримов**

Для опциональных немодельных стримов (Источники данных, Контроль моделей, Цифровые агенты, Потоковые данные) доступны действия «Активировать» / «Деактивировать». ПиРМ и ДАДМ - по умолчанию, без активации.

Активация раскрывает блок параметров стрима; деактивация сворачивает его и исключает из итоговой оценки. Деактивировать привлечение опционального стрима может автор анкеты.

## **3.12 Завершение заполнения анкеты**

После заполнения всех обязательных разделов кнопка «Завершить заполнение анкеты» активируется (иначе - подсказки о блокирующих разделах).

В модальном окне - «Завершить» или «Завершить и сохранить». Анкета переходит в «Заполнено», поля блокируются, действие необратимо. Аналитик качества модельных данных и Представитель стрима завершают только немодельные анкеты.

## **3.13 Блокировка (фиксация среза) анкеты**

Руководитель программ ДАДМ фиксирует срез анкеты по всем стримам на отчётную дату; анкета переходит в «Утверждена» и становится неизменной.

Продолжение работы - новой версией (§1.3). Действие отлично от завершения раздела и завершения анкеты.

## **3.14 Администрирование Смарт-Анкеты**

Административные функции по всем стримам: Прикладной администратор, Конфигуратор Смарт-Анкеты. Включает в том числе активацию и откат версии шаблона.

## **3.15 Чтение журналов аудита**

Просмотр журналов аудита по всем стримам: Прикладной администратор, Аудитор ИБ, Аудитор.

## **3.16. Сквозные и платформенные требования**

- **RBAC.** Разграничение доступа через разрешения Keycloak; backend при отсутствии права возвращает HTTP 403, недоступные UI-элементы полностью скрыты (недопустим показ кнопки с 403 по клику). Если действие недоступно по статусу, а не по праву, элемент отображается неактивным.
- **Конструктор шаблонов и справочники.** Конфигуратор Смарт-Анкеты или Прикладной администратор редактируют черновые версии шаблонов (структура блоков, параметры, логика) и публикует версии; управляет справочниками, осуществляют активацию опубликованной версии как текущей, а также ее откат.
- **Новая версия утверждённой анкеты.** Создаётся ролями с правом создания копированием данных из утверждённой версии; утверждённая версия остаётся неизменной.
- **Аудит значимых действий.** Логируются операции с шаблонами (создание, публикация, активация, откат, удаление) и с анкетами (создание, редактирование блока, завершение раздела, завершение анкеты, блокировка, новая версия, экспорт). Блокировка логируется с полным снепшотом содержимого анкеты.

# **6\. Рекомендации для разработчиков**

- **Пробрасывание ролей из смежных систем.** Проверить мапперы токена Keycloak: при переходе из СУМ / СУРМ / Data Lineage роли пробрасываются без «склеивания» несовместимых прав; сессия каждой системы имеет свой контекст.
- **Блочная модель прав.** Права редактирования, удаления и завершения раздела проверяются на паре «пользователь × блок», а не «пользователь × анкета». Редактирование блока разрешено, если стрим блока совпадает со стримом пользователя (за исключением не стримовых ролей). Статус анкеты «Завершено» возможен, когда все блоки «Заполнено».
- **Разделение завершения и блокировки.** Завершение раздела/анкеты - достуно множеству ролей (смотри матрицу), на уровне блока/анкеты, многократно. Блокировка - только Руководитель программ ДАДМ, фиксация неизменяемого среза.
- **Версионирование.** Блокировка не размораживается; продолжение работы - новой версией с переносом данных.
- **Фильтрация по стримам.** Фильтр применяется к списку, карточке и получению одной анкеты. Скрытие оценок чужих стримов - на уровне сериализации карточки: общая и детальная информация отдаются по всем стримам, оценки работ - только по стриму пользователя.
- **Аудит.** Логировать операции с шаблонами и анкетами; блокировку - со снепшотом. Доступ к журналам - Аудитор ИБ, Аудитор, Прикладной администратор.

# **7\. Открытые вопросы**

- **ОВ-1.** Асимметрия завершения у аналитиков: «Аналитик качества работы моделей ДАДМ» завершает раздел, но не анкету; «Аналитик качества модельных данных» - анкету (немодельную), но не раздел. Подтвердить у владельца процесса.
- **ОВ-2.** Правила редактирования общего блока «Общая информация» (владелец, порядок) требуют фиксации.
