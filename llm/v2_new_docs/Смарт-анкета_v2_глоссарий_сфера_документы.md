<a id="header-1"></a>__1\. Общие положения__

<a id="header-2"></a>__1\.1\. Назначение документа__

Документ описывает требования к приложению «Смарт\-анкета 2\.0» — инструменту оценки ML\-инициатив с интегральной оценкой сложности для планирования трудозатрат\.

Документ является основанием для:

• формирования бэклога разработки на итерации;

• заключения договорённостей со стримами о порядке поставки функциональности;

• приёмки результатов каждой итерации \(UAT\)\.

<a id="header-5"></a>__2\. Глоссарий__

__Термин__

__Определение__

__Смарт\-анкета__

__Инструмент количественной оценки ML\-инициативы, представляющий собой структурированный опросник\.__

__На основе взвешенных параметров \(тип ML\-задачи, готовность данных, каналы внедрения, риски, регуляторные требования и др\) вычисляет интегральный коэффициент сложности проекта для его приоритизации, планирования сроков и трудоёмкости\.__

__Архитектурный компонент__

__Типовой структурный элемент, представляющий отдельную функциональную область:__

__ __

__Термин__

__Определение__

__Модельный сервис__

__Автоматизированный сервис с API, предоставляющий результаты работы модели\.__

__Реализует полный пайплайн: получение запроса → предобработку входных данных → исполнение модели → постобработку → выдачу итогового результата\.__

__Модель__

__Количественный или качественный метод \(статистический, экономический, математический\), преобразующий входные данные в вероятностную оценку рисков или иную метрику для бизнес\-решений\. Характеризуется доверительным уровнем, отражающим степень модельного риска\.__

__Модель\-оркестратор \- это вид модели, который принимает в качестве входных данных выходные данные других моделей и комбинирует их оптимальным образом для получения окончательной, более точной и устойчивой оценки\.__

__Система\-источник__

__Внешний или внутренний поставщик исходных данных для модели\.__

__Объект / Витрина данных__

__Структурированный набор данных \(витрина\) внутри платформы для хранения и использования\.__

__Процесс обработки данных__

__Потоки и процедуры интеграции, трансформации и подготовки данных\.__

__Канал внедрения__

__Способ практического применения результатов модели \(интеграция в бизнес\-процесс или систему\); __

__Контроль модели__

__Непрерывный мониторинг и валидация качества, стабильности и точности работы модели\.__

__ __

__Состав типов компонентов считается фиксированным на текущий момент, однако архитектура системы должна допускать его расширение в будущем без переписывания механики\.__

__Параметр \(параметр архитектурного компонента, параметр\-триггер\)__

__Характеристика архитектурного компонента, которую пользователь задаёт в форме анкеты\. __

__Любой параметр компонента при задании его значения одновременно является триггером для поиска связанных типовых задач в справочнике\.__

__Параметры могут быть числовыми \(количество источников\), логическими \(да/нет, например «Источник новый»\), или справочными \(выбор из списка, например тип контроля\)\.__

__Состав параметров хранится в отдельном справочнике, расширяем без изменения кода — добавление нового параметра означает появление новой строки в справочнике, а не доработку логики приложения\.__

__Типовая работа__

__Единица работы, которая жёстко привязана к конкретной связке «Архитектурный компонент \+ значение его параметра»\.__

__Типовые задачи не создаются пользователем вручную — они автоматически подтягиваются системой из справочника, как только пользователь задаёт или изменяет значение параметра компонента\. __

__Каждая типовая задача несёт нормативную \(фиксированную\) оценку трудоёмкости в человеко\-днях, установленную методологом и хранящуюся в справочнике\.__

__Список типовых задач в анкете актуализируется реактивно: при изменении значения параметра задачи, условие которых перестало выполняться, исчезают; новые — появляются\.__

__Нетиповая работа__

__Единица работы, которая не привязана ни к одному архитектурному компоненту и не имеет нормативной оценки\. Нетиповые задачи отражают специфические активности конкретного стрима или проекта — то, что выходит за рамки типового сценария\. __

__Они добавляются пользователем вручную в отдельном разделе анкеты\. Пользователь самостоятельно указывает: название задачи, причину \(обоснование, почему задача не вписывается в типовое\), базовую оценку трудоёмкости в ч/д и коэффициент сложности или риска\.__

__Итоговая оценка задачи вычисляется по формуле: Итог = Оценка × Коэффициент\.__

__Каждая нетиповая задача явно включается или исключается из итоговой сметы через тоггл «Включить в расчёт»\.__

__Справочник типовых работ__

__Централизованный реестр правил, связывающих параметры архитектурных компонентов с конкретными работами и их нормативными оценками\.__

__Одна запись справочника описывает правило вида: «Если для компонента типа X задан параметр Y со значением Z — включить в анкету задачу N с оценкой M ч/д»\. Справочник является ключевым элементом расширяемости системы: добавление нового параметра или новой работы означает добавление строки в справочник, а не изменение кода механики\.__

__Нормативная оценка__

__Фиксированная оценка трудоёмкости в человеко\-днях, установленная для типовой задачи и хранящаяся в справочнике типовых задач\. Нормативная оценка отражает среднюю трудоёмкость выполнения данной работы при типовых условиях\. Пользователь не может изменить нормативную оценку в рамках анкеты — она задаётся методологом при наполнении справочника\. __

__Для нетиповых задач нормативной оценки нет: пользователь указывает произвольную базовую оценку, которая затем умножается на коэффициент\.__

__Коэффициент \(нетиповой задачи\)__

__Числовой множитель, применяемый к базовой оценке нетиповой задачи для учёта сложности, неопределённости или рисков\.__

__Итоговая оценка нетиповой задачи = Базовая оценка × Коэффициент\. Например, задача с оценкой 12 ч/д и коэффициентом 1\.5 даёт итог 18 ч/д\.__

__Диапазон и формат коэффициента \(фиксированный список или произвольный ввод\) подлежит согласованию с командой\.__

__Итоговая калькуляция__

__Суммарная оценка трудоёмкости анкеты, рассчитываемая автоматически на основе включённых задач\.__

__Складывается из двух составляющих: суммы нормативных оценок всех типовых задач с флагом «Включить в расчёт» = true, и суммы итоговых оценок \(Оценка × Коэффициент\) всех нетиповых задач с тем же флагом\. Результирующий показатель — Total — используется как основа для планирования ресурсов и согласования объёма работ по стриму или проекту__

__Шаблон \(Конфигуратор\)__

__JSON\-схема структуры анкеты\. Имеет версионность\.__

__Экземпляр анкеты__

__Заполненные данные, связанные с конкретной версией шаблона\.__

__Статус__

__Жизненный цикл анкеты \(Draft → Completed\)\.__

__Песочница \(What\-if\)__

__Тестовая копия анкеты для анализа влияния изменений коэффициентов без воздействия на основные данные\. __

<a id="header-6"></a>__3\. Концепция системы и метамодель__

<a id="header-7"></a>__3\.1\. Краткое описание__

«Смарт\-анкета» — это конфигурируемый опросник, структура которого задаётся JSON\-шаблоном\. Пользователь с определенными правами заполняет анкету, выбирая архитектурные компоненты и их параметры\.

На основании введённых данных система автоматически формирует список типовых задач из справочника и рассчитывает интегральную оценку трудозатрат в ч/д\. Пользователь может добавить нетиповые задачи вручную\. Анкета привлекает другие стримы ДАДМ через мультиселект — привлечённые стримы получают оповещения и заполняют свою часть\.

<a id="header-8"></a>__3\.2\. Иерархия данных__

Анкета → Раздел \(Тип 1 / 2 / 3\) → Группа \(Параметры / Компоненты / Задачи\)\.

• Тип 1 — «Общие сведения» \(статичный раздел\)

• Тип 2 — «Модельный стрим» \(статичный раздел\)

• Тип 3 — «Платформенные стримы» \(создаётся динамически по триггеру выбора стрима в Типе 2\)

<a id="header-21"></a>__8\. Дорожная карта__

<a id="header-22"></a>__Итерация 1 — MVP\-ядро__

__Цель: __Запустить рабочий конвейер «заполнение анкеты → расчёт → привлечение стримов → подтверждение → завершение»\.

__Критерии выхода: __все High\-FR приняты UAT; DS\-моделисты основных стримов \(РБ, КСМБ, ФМ, РНД\) могут полностью заполнить и завершить анкету; калькуляция воспроизводима; шаблон валиден; ошибок Sev\-1/2 нет\.

<a id="header-23"></a>__Итерация 2 — Реестр и финансирование__

__Цель: __Дать руководителям программ и проектному офису инструмент сквозного учёта инициатив\.

__Критерии выхода: __реестр используется руководителем программы для еженедельного обзора бэклога; выгрузка работает; фильтры покрывают потребности пилотных пользователей\.

<a id="header-24"></a>__Итерация 3 — Расширение функциональности__

__Цель: __Закрыть пробелы по архитектуре, ролевой модели, объектной модели и задачам развития\.

__Критерии выхода:__ ролевая модель развёрнута в продуктиве; справочники доступны для CRUD; пилотные стримы используют объектную модель\.

<a id="header-25"></a>__Итерация 4 — Версионность и What\-if__

__Цель: __Сделать систему устойчивой к смене шаблонов и коэффициентов\.

__Критерии выхода: __песочница используется минимум одним стримом для what\-if; пересчёт работает без потери данных; мажор/минор\-смена корректно обрабатывается\.

<a id="header-26"></a>__Итерация 5 — Административный UI__

__Цель: __Снизить нагрузку на разработку: 3\-я линия управляет справочниками и шаблонами без правки JSON и SQL\.

__Критерии выхода: __3\-я линия делает изменения справочников через UI; ручные правки JSON и SQL прекращены\.

<a id="header-27"></a>__9\. Матрица исключений \(Out of Scope\)__

Перечень требований, явно исключённых из всех итераций\. Перевод их обратно в скоуп возможен только через изменение настоящего SRS и согласование с PO\.
