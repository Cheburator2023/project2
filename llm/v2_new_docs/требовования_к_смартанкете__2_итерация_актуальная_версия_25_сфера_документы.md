<a id="header-1"></a>__1\. Основные положения__

Настоящий документ определяет требования к функциональным и нефункциональным характеристикам приложения "Смарт\-Анкета 2\.0", подлежащим реализации в первой итерации разработки\.

Документ является основанием для постановки задач команде разработки, формирования тестовой стратегии и приёмки результатов итерации\.

<a id="header-2"></a>__2\. Метамодель анкеты__

Анкета описывается иерархической конфигурацией\. Корневой объект анкеты содержит разделы, разделы — группы элементов, группы — параметры, архитектурные компоненты и работы\.

Структура иерархии и характеристики каждого уровня приведены в таблицах ниже\.

<a id="header-6"></a>__3\. Функциональные требования__

<a id="header-7"></a>__3\.1\. Конфигурация и версионирование__

__ФТ\-001__

__Описание структуры анкеты на основе конфигурационной схемы__

__Структура анкеты должна описываться в конфигурационных файлах на стороне сервера, а не фиксироваться в программном коде\.__

__*Состав описываемых элементов*__

__Разделы анкеты и условия их отображения__

__Группы элементов внутри разделов__

__Архитектурные компоненты и допустимое число их экземпляров__

__Параметры компонентов и правила их представления__

__Правила связи параметров со справочником типовых работ__

__*Технические особенности*__

__Формат конфигурационных файлов — JSON__

__Конфигурация загружается на стороне сервера и применяется при создании каждой новой анкеты__

__Изменение конфигурации одного стрима не должно затрагивать конфигурации других стримов__

__ФТ\-002__

__Хранение параметров и допустимых значений в справочниках__

__Перечень параметров каждого архитектурного компонента и содержимое всех элементов выбора значений должны храниться в справочниках на стороне сервера\.__

__*Состав справочников*__

__Перечень параметров — отдельный справочник для каждого типа архитектурного компонента__

__Содержимое выпадающих списков, групп переключателей и групп флажков — соответствующие справочники допустимых значений__

__Все справочники подгружаются в форму анкеты динамически__

__*Принцип расширяемости*__

__Добавление нового параметра выполняется добавлением записи в справочник__

__Добавление нового допустимого значения выполняется добавлением записи в соответствующий справочник__

__Модификация программного кода для подобных изменений не требуется__

__ФТ\-003__

__Отображение только активных элементов справочников__

__В форме анкеты должны отображаться только записи справочников, имеющие активный признак__

__Деактивированные записи должны сохраняться в анкетах, созданных до момента деактивации__

__Деактивированные записи не должны предлагаться для выбора в новых анкетах__

__ФТ\-004__

__Валидация конфигурационной схемы__

__Загружаемая конфигурационная схема должна проходить валидацию по формальным правилам до сохранения и активации\.__

__При обнаружении ошибки система должна возвращать развёрнутое сообщение с указанием пути к проблемному элементу__

__Невалидная схема не должна заменять текущую активную__

__Результат валидации должен фиксироваться в журнале аудита__

__ФТ\-005__

__Активация версии конфигурационной схемы__

__В каждый момент времени должна быть активна ровно одна версия конфигурационной схемы__

__При смене активной версии ранее созданные анкеты не должны пересчитываться автоматически__

__Действие активации должно фиксироваться в журнале аудита с указанием пользователя, даты, времени и идентификатора версии__

__ФТ\-006__

__Формат номера версии конфигурационной схемы__

__Каждая версия конфигурационной схемы должна иметь уникальный идентификатор и номер в формате «мажорная\.минорная»\.__

__*Мажорная версия*__

__Фиксирует изменения, затрагивающие логику расчёта трудоёмкости: состав параметров, весовые коэффициенты, структуру зависимостей между параметрами и работами\.__

__*Минорная версия*__

__Фиксирует изменения, не затрагивающие расчёт: метки полей, порядок отображения, тексты подсказок, признаки активности справочных значений\.__

__ФТ\-007__

__Фиксация версии конфигурационной схемы у анкеты__

__Каждая заполненная анкета должна хранить ссылку на версию схемы, в соответствии с которой она была создана__

__При открытии существующей анкеты система должна использовать именно ту версию схемы, которая зафиксирована в её атрибутах__

__Изменения конфигурации, выполненные после создания анкеты, не должны влиять на ранее сохранённые анкеты__

__*Примечание\. Просмотр истории версий, откат и пересчёт сохранённых анкет по новой версии схемы реализуются в последующих итерациях\.*__

__ФТ\-008__

__Ручное управление конфигурацией в первой итерации__

__• Редактирование конфигурационных файлов выполняется силами разработчика__

__• Наполнение справочников выполняется силами разработчика или уполномоченными сотрудниками сопровождения через интерфейсы баз данных__

__• Графический административный интерфейс реализуется в последующих итерациях__

<a id="header-8"></a>__3\.2\. Архитектурные компоненты__![image.png](требовования_к_смартанкете__итерация_25_сфера_документы_media/image_002.png)



__ФТ\-009__

__Управление экземплярами архитектурных компонентов__

__В рамках одной анкеты пользователь должен иметь возможность добавить несколько экземпляров одного типа архитектурного компонента \(за исключением модельного сервиса в рамках первой итерации\), если иное не ограничено конфигурационной схемой__

__*Свойства экземпляра*__

__• Уникальный идентификатор__

__• Независимый набор значений параметров__

__• Собственный перечень связанных типовых работ__

__ФТ\-010__

__Удаление экземпляра архитектурного компонента__

__• Удаление должно выполняться с явным подтверждением пользователя__

__• При удалении все связанные типовые работы должны удаляться автоматически__

__• Итоговая калькуляция должна пересчитываться по факту удаления__

__*См\. также: ФТ\-016 \(формирование типовых работ\), ФТ\-026 \(итоговая калькуляция\)*__

__ФТ\-011__

__Учёт области использования витрины данных__

__Для архитектурного компонента «Витрина данных» должна быть предусмотрена возможность указания области её использования внутри одного модельного сервиса\.__

__• Витрина связывается с одной или несколькими моделями того же модельного сервиса__

__• Трудоёмкость разработки витрины учитывается в калькуляции единожды независимо от числа связанных моделей__

__• При изменении состава связанных моделей итоговая калькуляция пересчитывается__

__*Примечание\. Поддержка общей витрины, обслуживающей модели из разных модельных сервисов, реализуется в последующих итерациях\.*__

__ФТ\-012__

__Матрица типов алгоритмов моделей__

__В разделах, содержащих сведения о моделях, должен быть реализован табличный механизм фиксации каскадов и ансамблей моделей в виде матрицы «тип алгоритма — количество моделей»\.__

__*Состав колонок*__

__• Тип алгоритма — выбор из справочника типов алгоритмов__

__• Количество моделей — целое положительное число__

__• Весовой коэффициент — отображается из справочника, не редактируется \(см\. ФТ\-014\)__

__*Поведение*__

__• Строки матрицы добавляются и удаляются динамически без ограничения сверху__

__• Согласованность матрицы контролируется требованием ФТ\-013__

__ФТ\-013__

__Контроль согласованности матрицы типов алгоритмов__

__• Сумма значений в колонке количества моделей должна совпадать с общим заявленным числом моделей модельного сервиса__

__• При несовпадении в интерфейсе отображается предупреждение с указанием контрольной суммы \(заявлено / введено\)__

__• При несовпадении переход анкеты в статус «Завершено» должен быть заблокирован__

__ФТ\-014__

__Отображение весового коэффициента типа алгоритма__

__• Весовой коэффициент каждого типа алгоритма отображается рядом с его наименованием в матрице__

__• Значение коэффициента подгружается из справочника типов алгоритмов__

__• Поле коэффициента не доступно для редактирования из карточки анкеты__

__• При наведении на значение коэффициента отображается подсказка о его источнике__

__ФТ\-015__

__Создание карточек моделей при завершении анкеты__

__При переходе анкеты в статус «Завершено» для каждой модели должна автоматически создаваться соответствующая карточка в системе управления моделями\.__

__*Состав атрибутов карточки*__

__• Наименование модели__

__• Тип алгоритма__

__• Ссылка на исходную анкету__

__*Поведение при повторном завершении*__

__При повторном переводе анкеты в «Завершено» ранее созданные карточки должны обновляться без дублирования\.__



<a id="header-9"></a>__3\.3\. Типовые работы__

__ФТ\-016__

__Автоматическое формирование перечня типовых работ__

__При задании или изменении значения параметра архитектурного компонента система должна выполнять поиск в справочнике типовых работ по совокупности условий: тип компонента, наименование параметра, значение параметра\.__

__*Поведение перечня*__

__• Работы, условие включения которых выполнено, добавляются в перечень автоматически с нормативной оценкой из справочника__

__• Работы, условие включения которых перестало выполняться, исключаются из перечня__

__• При удалении параметра или экземпляра компонента все связанные с ними типовые работы удаляются__

__*См\. также: ФТ\-026 \(пересчёт итоговой калькуляции\)*__

__ФТ\-017__

__Запрет ручного редактирования типовых работ__

__Состав и параметры типовых работ должны определяться исключительно справочником типовых работ\. Пользователь не должен иметь возможности их изменять\.__

__*Запрещённые действия пользователя*__

__• Добавление типовой работы вручную__

__• Удаление типовой работы \(за исключением каскадного удаления при изменении параметра\)__

__• Изменение наименования типовой работы__

__• Изменение нормативной оценки типовой работы__

__*Реализация запрета*__

__• Соответствующие поля в интерфейсе отображаются в режиме «только чтение»__

__• Попытки изменения через программный интерфейс отклоняются с возвратом стандартизированной ошибки доступа__

__ФТ\-018__

__Управление нормативными оценками__

__• Нормативные оценки типовых работ устанавливаются централизованно через справочник типовых работ__

__• Изменение нормативной оценки в справочнике не влияет на ранее завершённые анкеты__

__• Влияние изменения на анкеты в статусе «Черновик» определяется версионированием конфигурационной схемы \(ФТ\-006, ФТ\-007\)__



<a id="header-10"></a>__3\.4\. Нетиповые работы__

__ФТ\-019__

__Добавление нетиповых работ__

__• Пользователь должен иметь возможность добавить неограниченное количество нетиповых работ__

__• Нетиповые работы располагаются в специально выделенной группе раздела__

__• Назначение нетиповых работ — отражение активностей, не охватываемых нормативным справочником__

__ФТ\-020__

__Состав атрибутов нетиповой работы__

__Нетиповая работа должна описываться следующими атрибутами\.__

__*Обязательные атрибуты*__

__• Наименование — текстовое значение__

__• Тип работ — значение из методологического справочника типов работ__

__• Базовая оценка трудоёмкости — целое положительное число \(человеко\-дней\)__

__• Коэффициент сложности — положительное число; диапазон задаётся справочником \(см\. ОВ\-003\)__

__*Системные атрибуты*__

__• Признак включения в итоговый расчёт — логический атрибут, по умолчанию активен__

__• Итоговая оценка трудоёмкости — рассчитываемое значение, недоступное для прямого ввода \(см\. ФТ\-021\)__

__ФТ\-021__

__Расчёт итоговой оценки нетиповой работы__

__• Итоговая оценка трудоёмкости нетиповой работы вычисляется автоматически как произведение базовой оценки и коэффициента сложности__

__• Поле итоговой оценки отображается в интерфейсе и обновляется при изменении базовой оценки или коэффициента__

__• Прямое редактирование итоговой оценки не допускается__

__ФТ\-022__

__Признак включения нетиповой работы в расчёт__

__Каждая нетиповая работа должна иметь логический признак включения в итоговую калькуляцию\.__

__*Назначение*__

__Признак позволяет пользователю исключить из расчёта работу, формально присутствующую в перечне, но не выполняемую в рамках конкретного проекта, с сохранением её видимости в перечне\.__

__*Поведение*__

__• Значение по умолчанию при добавлении новой нетиповой работы — «активен»__

__• При деактивации признака работа сохраняется в перечне, но не учитывается в итоговой калькуляции__

__• Изменение значения признака вызывает незамедлительный пересчёт итоговой калькуляции__

__*Примечание\. Признак применяется только к нетиповым работам\. Типовые работы участвуют в калькуляции в полном объёме согласно справочнику\.*__

__ФТ\-022__

__Валидация обязательных атрибутов нетиповой работы__

__• Сохранение нетиповой работы блокируется при незаполненных обязательных атрибутах__

__• У каждого незаполненного обязательного поля отображается соответствующее сообщение__

__• Диапазон допустимых значений коэффициента сложности определяется методологом и фиксируется на уровне справочника__

__*См\. также: ФТ\-020 \(состав атрибутов\), ОВ\-003 \(диапазон коэффициента сложности\)*__



<a id="header-11"></a>__3\.5\. Расчёт итоговой трудоёмкости__

__ФТ\-024__

__Мультипликативная модель расчёта__

__Расчёт итоговой трудоёмкости должен строиться на единой мультипликативной модели без индивидуальных формул для каждого стрима\.__

__*Последовательность расчёта*__

__• Параметры каждой группы элементов образуют локальный коэффициент путём перемножения соответствующих весовых значений__

__• Локальные коэффициенты групп перемножаются между собой, давая итоговый коэффициент раздела__

__• Итоговая оценка трудоёмкости каждой типовой работы — произведение нормативной оценки и итогового коэффициента__

__*Свойство модели*__

__Перемещение параметра между группами или компонентами не требует переписывания формулы — весовой коэффициент параметра следует за ним\.__

__ФТ\-025__

__Приоритетный режим расчёта__

__В дополнение к мультипликативной модели должен поддерживаться приоритетный режим расчёта, в котором применяется первый сработавший коэффициент в порядке, заданном в справочнике\.__

__• Режим расчёта задаётся в конфигурационной схеме__

__• Значение по умолчанию — мультипликативный режим__

__• Документация по обоим режимам с числовыми примерами предоставляется методологом__

__ФТ\-026__

__Расчёт итоговой калькуляции анкеты__

__Итоговая оценка трудоёмкости по анкете должна рассчитываться автоматически как сумма двух составляющих\.__

__*Составляющие итоговой калькуляции*__

__• Сумма итоговых оценок всех типовых работ анкеты__

__• Сумма итоговых оценок нетиповых работ, имеющих активный признак включения в расчёт \(см\. ФТ\-022\)__

__*Поведение*__

__• Значение пересчитывается при любом изменении состава или атрибутов работ__

__• Источником истины при расхождении значений в интерфейсе и на сервере является серверный расчёт__

__ФТ\-027__

__Отображение итоговой калькуляции__

__• Итоговая калькуляция отображается на экране редактирования анкеты с разбивкой на сумму по типовым работам, сумму по нетиповым работам и совокупное значение__

__• При наличии нескольких точек отображения итоговой калькуляции на одном экране значения должны быть идентичны__

__• Окончательный формат представления итоговой калькуляции уточняется методологом \(см\. ОВ\-001\)__



<a id="header-12"></a>__3\.6\. Привлечение поддерживающих стримов__

__ФТ\-028__

__Мультивыбор поддерживающих стримов__

__• В разделе модельного стрима реализуется мультиселект для выбора поддерживающих стримов__

__• Список доступных стримов подгружается из справочника поддерживающих стримов__

__• Допускается выбор произвольного числа стримов, включая отсутствие выбора__

__• В мультиселекте реализован поиск по наименованию стрима__

__ФТ\-029__

__Автоматическое создание разделов поддерживающих стримов__

__• При сохранении выбора в анкете автоматически создаются разделы соответствующих стримов__

__• Разделы предзаполняются перечнями типовых работ, относящихся к области ответственности стрима__

__• Удаление стрима из выбора вызывает удаление соответствующего раздела с подтверждением пользователя при наличии заполненных данных__

__ФТ\-030__

__Автоматическое оповещение привлечённых стримов__

__При сохранении выбора поддерживающих стримов представители привлечённых стримов должны получать автоматическое уведомление\.__

__*Канал доставки*__

__В первой итерации — корпоративная электронная почта \(см\. ОВ\-005 по составу каналов в последующих итерациях\)\.__

__*Состав уведомления*__

__• Ссылка на анкету__

__• Наименование автора анкеты__

__• Опциональный комментарий автора \(см\. ФТ\-031\)__

__*Защита от дублирования*__

__Повторное привлечение того же стрима в течение одного часа не должно порождать повторного уведомления\.__

__ФТ\-031__

__Комментарий при привлечении стрима__

__• Автор анкеты может задать опциональный текстовый комментарий, сопровождающий привлечение стримов__

__• Максимальная длина комментария — 2000 символов__

__• Комментарий включается в текст уведомления \(ФТ\-030\)__

__• Комментарий отображается представителю стрима при открытии его раздела__

__ФТ\-032__

__Индикация состояния разделов поддерживающих стримов__

__Для каждой анкеты на стартовом экране автора отображается состояние заполнения по каждому привлечённому стриму в виде цветовых маркеров\.__

__*Значения индикатора*__

__• Красный — раздел стрима требует заполнения или ещё не подтверждён__

__• Зелёный — раздел стрима заполнен и подтверждён__

__*Доступность*__

__• Цветовое решение дублируется подписями и формой маркера для пользователей с нарушениями цветовосприятия__

__• Состояние маркеров обновляется без перезагрузки страницы или при возврате на стартовый экран__



<a id="header-13"></a>__3\.7\. Контроль модели и качество данных__

__ФТ\-033__

__Указание типа рекалибровки модели__

__В разделе модельного стрима должно быть предусмотрено поле «Тип рекалибровки»\.__

__*Допустимые значения*__

__• Полная__

__• Частичная__

__• Калибровка порогов__

__*Поведение*__

__• Каждому значению соответствует коэффициент в справочнике коэффициентов рекалибровки__

__• При изменении типа итоговая калькуляция пересчитывается \(см\. ФТ\-026\)__

__• Поле обязательно, если в опроснике контроля данных активирован признак «Рекалибровка» \(см\. ФТ\-034\)__

__ФТ\-034__

__Опросник контроля данных__

__В разделе модельного стрима должен быть реализован опросник контроля данных\.__

__*Состав признаков*__

__• Рекалибровка__

__• Другой канал__

__• Переработка__

__• Новый тип модели__

__• Разные контуры__

__• Структура логов__

__• Контроль каскада__

__*Свойства полей*__

__• Каждый признак представлен логическим полем \(флажком\)__

__• Все признаки опционально заполняемые__

__• К каждому признаку прилагается текстовая подсказка, доступная при наведении__

__ФТ\-035__

__Указание вида мониторинга модели__

__• В разделе модельного стрима предусмотрено комбинированное поле «Вид мониторинга»__

__• Допускается выбор значения из справочника видов мониторинга или ввод произвольного текста__

__• Поле опциональное__

__• Максимальная длина произвольного текста — 500 символов__



<a id="header-14"></a>__3\.8\. Статусная модель и завершение анкеты__

 ![image.png](требовования_к_смартанкете__итерация_25_сфера_документы_media/image_003.png)

__ФТ\-036__

__Жизненный цикл анкеты__

__• Анкета имеет два основных статуса: «Черновик» и «Завершено»__

__• Переходы между статусами соответствуют таблице статусной модели__

__• Изменение статуса фиксируется в журнале аудита__

__ФТ\-037__

__Подтверждение раздела поддерживающего стрима__

__Каждый раздел поддерживающего стрима должен содержать действие подтверждения заполнения, доступное его представителю\.__

__*Поведение при подтверждении*__

__• При выполнении действия открывается модальное окно с предварительным просмотром заполненных данных и итоговой оценкой по разделу__

__• Подтверждение требует явного действия пользователя__

__• После подтверждения раздел переходит в локальное состояние «Готово»__

__• Поля подтверждённого раздела блокируются для редактирования__

__ФТ\-038__

__Блокировка перехода анкеты в статус «Завершено»__

__Переход анкеты в статус «Завершено» возможен исключительно при подтверждении всех обязательных разделов\.__

__*Реализация блокировки*__

__• При наличии неподтверждённых обязательных разделов действие перевода в интерфейсе недоступно__

__• Рядом с заблокированным действием отображается подсказка о причине__

__• Попытка перевода через программный интерфейс отклоняется с возвратом стандартизированной ошибки__

__• Ответ программного интерфейса содержит перечень неподтверждённых разделов__

__ФТ\-039__

__Защита полей анкеты в статусе «Завершено»__

__• После перевода анкеты в «Завершено» все её поля становятся недоступными для редактирования__

__• Поля в интерфейсе отображаются в режиме «только чтение»__

__• Попытки изменения через программный интерфейс отклоняются с возвратом стандартизированной ошибки__

__ФТ\-040__

__Создание копии завершённой анкеты__

__Из анкеты в статусе «Завершено» должна быть предусмотрена возможность создания её редактируемой копии для продолжения работы с данными\.__

__*Условия выполнения*__

__• Действие доступно только для анкет в статусе «Завершено»__

__• Действие доступно пользователям стрима исходной анкеты в соответствии с моделью видимости \(см\. раздел 3\.9\)__

__• Перед созданием копии система запрашивает подтверждение пользователя__

__*Состав копируемых данных*__

__• Все значения параметров, экземпляры архитектурных компонентов и нетиповые работы__

__• Состав привлечённых стримов и заполненные ими разделы__

__• Ссылка на ту же версию конфигурационной схемы, что и в исходной анкете\.__

__*Состояние копии после создания*__

__• Копия создаётся в статусе «Черновик» с новым уникальным идентификатором__

__• Автором копии указывается пользователь, выполнивший действие; в копии сохраняется ссылка на исходную анкету__

__• Локальный статус подтверждения всех разделов поддерживающих стримов в копии сбрасывается__

__• Карточки моделей в системе управления моделями повторно не создаются__

__• При сохранении состава привлечённых стримов в копии повторное оповещение этих стримов не отправляется__

<a id="header-15"></a>__3\.9\. Список анкет__

__ФТ\-041__

__Отображение списка анкет__

__Список анкет является стартовым экраном системы и обеспечивает пользователю обзор анкет, входящих в зону его видимости, с быстрым переходом к редактированию или просмотру каждой\.__

__*Состав отображаемых колонок*__

__ID анкеты __

__Наименование анкеты__

__Департамент заказчика__

__Стрим\-исполнитель__

__Версия анкеты__

__Статус \(«Черновик» или «Завершено\)__

__Итоговая оценка трудоёмкости — значение итоговой калькуляции__

__Дата создания__

__Дата последнего изменения — дата последнего изменения анкеты или её разделов__

__*Состояние пустого списка*__

__При отсутствии доступных анкет отображается сообщение об отсутствии анкет и предложение создать новую\.__

__ФТ\-042__

__Видимость анкет в списке__

__В первой итерации применяется модель совместной видимости в пределах стрима\.__

__*Правило видимости*__

__• Автор анкеты видит все анкеты своего стрима, включая анкеты, созданные другими членами стрима__

__• Представитель стрима видит все анкеты, в которых привлечён его стрим, независимо от автора__

__• Анкеты других стримов в списке не отображаются__

__ФТ\-043__

__Фильтрация списка анкет__

__Список анкет должен поддерживать фильтрацию по всем отображаемым колонкам\.__

__*Состав фильтров*__

__ID анкеты \- поиск по подстроке без учёта регистра и/или выбор из списка__

__Наименование анкеты \- поиск по подстроке без учёта регистра и/или выбор из списка__

__Департамент заказчика \- выбор одного или нескольких значений из списка, доступных пользователю__

__Стрим\-исполнитель \- выбор одного или нескольких значений из списка, доступных пользователю__

__Версия анкеты \- поиск по подстроке без учёта регистра и/или выбор из списка__

__Статус \- выбор значений «Черновик» и \(или\) «Завершено»__

__Итоговая оценка трудоёмкости — диапазон значений \(от — до\), обе границы опциональные__

__Дата создания \- диапазон дат с возможностью указания начальной и конечной даты, обе границы опциональные__

__Дата последнего изменения —аналогично периоду создания__

__*Поведение фильтров*__

__• Несколько одновременно установленных фильтров применяются по логике «И»__

__• Текущие значения фильтров отображаются в виде набора удаляемых тегов над списком__

__• Доступна операция полного сброса фильтров одним действием__

__• Состав значений фильтра подгружается только из анкет, входящих в зону видимости пользователя__

__ФТ\-044__

__Сортировка списка анкет__

__Список анкет должен поддерживать сортировку по любой отображаемой колонке\.__

__• Сортировка осуществляется кликом по заголовку колонки__

__• Поддерживаются направления: по возрастанию и по убыванию__

__• Активная колонка сортировки и направление отображаются индикатором у заголовка__

__• Сортировка по умолчанию — по дате последнего изменения, по убыванию__

__ФТ\-045__

__Создание новой анкеты__

__Со страницы списка анкет должно быть доступно действие создания новой анкеты\.__

__• Действие доступно пользователям, имеющим право создавать анкеты в своём модельномстриме__

__• При нажатии создаётся новая анкета в статусе «Черновик» с автором, равным текущему пользователю__

__• Новая анкета создаётся по активной версии конфигурационной схемы__

__• После создания пользователь автоматически переходит к экрану редактирования анкеты__

__ФТ\-046__

__Действия со строкой списка__

__Каждая строка списка анкет должна предоставлять набор действий, доступных пользователю с учётом его роли и статуса анкеты\.__

__*Доступные действия*__

__• Открыть — переход к экрану анкеты — в режиме редактирования для статуса «Черновик» или в режиме просмотра для статуса «Завершено»__

__• Создать копию — доступно для анкет в статусе «Завершено»__

__*Поведение*__

__• Действие открытия выполняется кликом по наименованию анкеты или по соответствующему пункту контекстного меню строки__

__• Прочие действия доступны через контекстное меню строки__

__• Действия, недоступные пользователю в текущем контексте, в меню не отображаются__

Это является задачей аналитического моделирования, которая будет идти параллельно\. Предусмотреть, что добавление новых параметров в будущем не должно требовать переписывания всей механики\.
