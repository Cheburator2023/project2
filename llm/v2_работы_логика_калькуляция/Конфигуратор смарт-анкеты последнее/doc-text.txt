 1. Описание пользовательской истории
Я как
Архитектор данных / Офицер данных / Администратор смарт-анкеты (пользователь с ролью «Архитектор смарт-анкеты»)
Хочу
Иметь экран «Типовые работы», на котором для каждой работы из справочника настраиваются триггеры появления, коэффициенты параметров трудоёмкости (в разрезе стрима-исполнителя), нормы трудозатрат (с историчностью и стримом-исполнителем) и формула расчёта итогового значения с правилами округления
Для того, чтобы
Поддерживать справочник типовых работ и конфигурацию формул в версии шаблона анкеты без участия разработчика; гарантировать, что в анкету попадают только те работы, у которых сработали условия-триггеры
2. Контекст
Смарт-анкета — конфигуратор оценки трудозатрат по типовым работам в разрезе типов архитектурных компонентов (Система-источник, Объект / Витрина данных, Процесс обработки данных, Модель, Модельный сервис) и стримов-исполнителей.
Раздел «Логика» → «Типовые работы» — экран администрирования справочника типовых работ и их конфигурации в редактируемой версии шаблона анкеты.
На текущий момент в справочнике порядка 148 работ. В UI группируются по типу архитектурного компонента.
Ключевое правило:
• Типовая работа автоматически подставляется в анкету только при срабатывании всех условий-триггеров. Триггер — это набор из одного или более одновременно выполняемых условий (объединение логическим «И»).
• Работа без триггеров в анкету не попадает и в расчёте не участвует. Такое состояние допустимо как промежуточное (черновик), но фиксируется в UI явным статусом «без триггеров — не появится в анкете».
• Параметры трудоёмкости — коэффициенты на комбинацию (работа, параметр, значение, стрим-исполнитель). Используются как множители в формуле.
• Нормы трудозатрат — список значений нормы по комбинации (работа, стрим-исполнитель) с историчностью (даты начала и окончания действия). На дату расчёта анкеты выбирается актуальная норма.
• Параметры и значения параметров — глобальные справочники, на которые ссылаются условия и коэффициенты. Значения хранятся в JSON с историчностью и порядком сортировки.
• Формула и округление — часть «Файла конфигурации» Версии шаблона. Редактируются на этом же экране; при сохранении могут порождать новую минорную версию шаблона (правило версионирования вынесено в отдельную спецификацию).

4. Общая структура экрана
№
Зона экрана
Состав
Поведение
1
Сегмент-переключатель раздела
Два сегмента: «Типовые работы» (по умолчанию), «Зависимости параметров».
Подсказка раскрывает назначение вкладки.
Переключение без перезагрузки страницы.
Состояние вкладки сохраняется в URL.
2
Шапка раздела
Счётчик «N работ, сгруппированы по архитектурному компоненту».
Переключатель вида: Дерево / Таблица / Карточки.
Счётчик пересчитывается при добавлении/удалении.
Выбранный вид запоминается на сессию.
3
Левая панель — список работ
Заголовок «Архитектурные компоненты» + кнопка «+ Работа».
Дерево: тип арх. компонента (с счётчиком) → элементы работ.
У каждого элемента: название, актуальная норма (на сегодня для выбранного стрима), бейдж стрима-исполнителя, статус-метка («появляется» либо «без триггеров»).
Клик по группе — свернуть/развернуть; клик по работе — загрузка карточки справа одним запросом.
Кнопка «+ Работа» — форма создания.
4
Шапка карточки работы
Название работы, бейдж типа архитектурного компонента, переключатель «Стрим-исполнитель» (выпадающий список доступных стримов).
Селектор стрима меняет видимые блоки: условия, коэффициенты параметров и нормы отображаются для выбранного стрима.
Стрим выбирается из доступных для типа архитектурного компонента работы.
Запоминается на сессию пользователя.
При смене стрима блоки ниже перерисовываются без перезагрузки карточки.
5
Тело карточки — блоки
«Нормы трудозатрат» (список с историчностью),
«Условия появления работы» (триггеры), 
«Параметры трудоёмкости» (коэффициенты), 
«Конструктор формулы», 
«Округление», 
«Превью результата».
Все блоки редактируются построчно. 
Превью пересчитывается мгновенно.

4
Список норм по работе
Минимум 1 запись для каждой комбинации (работа, стрим-исполнитель), участвующей в расчёте

19
Коэффициенты по значениям параметра
Всегда (внутри элемента)
Для каждого действующего значения параметра — отдельный коэффициент. Коэффициент — неотрицательное дробное число (до двух знаков после точки).
Дефолтное значение — 1.

6. Работы в разрезе спецификации
6.1 Backend
№
Описание
1
API на чтение справочника типовых работ: с фильтрацией по типу архитектурного компонента, стриму-исполнителю и пагинацией.
2
API на карточку работы: возвращает работу с разрезом по выбранному стриму
3
API на изменение: payload содержит поля работы и/или массивы с указанием стрима.Каждое поле валидируется отдельно, бэкенд возвращает массив ошибок с указанием пути.
4
Валидация имени: 1…255
5
Валидация норматива: каждая запись ≥ 0 (decimal до 2 знаков).
validFrom — обязательна;
validTo — опциональна, при наличии > validFrom.
Периоды одной (работа, стрим) не должны пересекаться.
На дату расчёта анкеты для (работа, стрим) должна быть ровно одна действующая запись — инвариант проверяется при сохранении.
6
Валидация триггеров (условий): каждая запись параметра должен ссылаться на действующую запись справочника «Параметры»; valueId — на действующее значение из «Значения параметров» для paramId. operator — из словаря, для нечисловых значений допустимы только = и ≠.
7
Валидация параметров трудоемкости: каждая запись — { stream, paramId, valueId, coefficient }. coefficient ≥ 0.
Уникальность по тройке (stream, paramId, valueId) в пределах одной работы.
8
Валидация формулы: парсер выражения над токенами { N (норма), P(paramId) (коэффициент параметра), число, оператор +−×÷, скобки }.
P(paramId) допустим только если paramId присутствует в laborCoefficients работы. При нарушении — ошибка с указанием позиции в исходной строке формулы.
9
Валидация rounding: { mode ∈ {CEIL, FLOOR, ROUND, NONE}, step }; шаг обязателен и в [0.0001; 1000], если mode ≠ NONE; при mode = NONE step игнорируется и в payload может отсутствовать.
10
Расчёт превью: вход — { stream, atDate, answers: { paramId: valueId } }. Сервер выбирает действующую на дату норму, действующие значения параметров и коэффициенты, выполняет подстановку в формулу, применяет округление и возвращает расчет или ошибку с указанием причины.
11
Удаление работы: каскадно удаляет связанные нормы, условия и коэффициенты в справочной части; перед удалением возвращает информацию о версиях анкеты, где работа уже учтена, чтобы фронт мог запросить подтверждение.
12
Логика «работа подставляется в анкету только при срабатывании всех её условий» реализуется в сервисе расчёта Версии анкеты.
Работы с пустым массивом условий для (работа, стрим) исключаются из расчёта.
13
Версионирование шаблона при изменении формулы или округления
6.2 Frontend
№
Описание
1
Реализовать экран двухпанельным layout: слева — список работ, справа — карточка выбранной работы.
2
Сегмент-переключатель раздела «Типовые работы / Зависимости параметров» — состояние сохраняется в URL.
3
Переключатель вида «Дерево / Таблица / Карточки» — в первой итерации реализовать только «Дерево»; «Таблица» и «Карточки» — заглушка «Будет реализовано позже».
4
В дереве работ: группа типа архитектурного компонента сворачивается/раскрывается; рядом с названием — счётчик работ в группе.
Выбранная работа визуально выделена; рядом с каждой работой — компактный набор меток (тип архитектурного компонента, стрим-исполнитель, статус-метка «появляется» либо «без триггеров»).
5
Шапка карточки работы — селектор стрима-исполнителя.
При смене стрима блоки «Нормы», «Условия», «Параметры трудоёмкости» перерисовываются по соответствующему разрезу.
Состояние выбранного стрима запоминается на сессию пользователя (per-user-per-work) и подставляется при следующем открытии карточки.
6
Карточка работы — стек блоков, каждый — отдельный компонент: редактор нормативов (список с историчностью), редактор условий (триггеров), редактор параметров трудоемкости, редактор формул, редактор округления, карточка предпросмотра.
7
Редактор нормативов: таблица записей со столбцами «Норма», «Дата начала», «Дата окончания», действиями. Валидация перекрытия периодов выполняется на клиенте (быстрая обратная связь) и подтверждается ответом бэкенда.
8
Редактор триггеров (условий) :список условий в виде grid (параметр, оператор, значение, действие удалить). Над списком — статус-плашка триггера. Кнопка «+ Условие» в шапке блока; недоступна, если в шапке карточки не выбран стрим.
9
Редактор коэффициентов трудоемкости: на каждый параметр трудоёмкости — раскрывающаяся секция с таблицей коэффициентов по значениям. Текущее значение из последнего черновика расчёта анкеты выделяется.
10
Редактор формул: два режима — «Визуально» (drag-and-drop чипов) и «Вручную» (текст с парсером).
Парсер выражений — общий с бэкендом.
Кнопка «Коэффициент параметра» в палитре отключена, если у работы нет ни одного параметра трудоёмкости. При попытке отредактировать формулу в опубликованной версии шаблона — модалка о создании минорной версии.
11
Редактор округления: выбор режима и шага. При режиме «Без округления» поле шага становится недоступным.
12
Превью с параметрической формулой: пересчёт на клиенте при любом изменении).
Кнопка «Сверить с сервером» — отправляет запросы и сравнивает результаты; при расхождении — предупреждение с возможностью открыть отладочный вывод обоих расчётов.
13
Автосохранение. Индикатор статуса в шапке карточки. При ошибке — уведомление + действие «Повторить». Локальный буфер на случай сетевых сбоев.
14
Числовые поля принимают на ввод как «.», так и «,», на отправку нормализуют в «.».
Поля дат — стандартный datepicker с форматом ДД.ММ.ГГГГ; вводимое значение валидируется на формат и на логическую корректность периода.
15
Подсказки к параметрам подтягиваются из атрибута «Описание (подсказка)» сущности «Параметры».
