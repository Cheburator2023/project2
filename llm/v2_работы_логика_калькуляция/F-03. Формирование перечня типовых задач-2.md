**2 Контекст**

**Смартанкета** — конфигуратор оценки трудозатрат по типовым работам в разрезе типов архитектурных компонентов Системаисточник, Объект / Витрина данных, Процесс обработки данных, Модель, Модельный сервис и стримовисполнителей

Раздел «Логика» → «Типовые работы» — экран администрирования справочника типовых работ и их конфигурации в редактируемой версии шаблона анкеты

На текущий момент в справочнике порядка 148 работ В UI группируются по типу архитектурного компонента

**Ключевое правило:**

• Типовая работа автоматически подставляется в анкету только при срабатывании всех условийтриггеров Триггер — это набор из одного или более одновременно выполняемых условий объединение логическим «И»

• Работа без триггеров в анкету не попадает и в расчёте не участвует Такое состояние допустимо как промежуточное черновик, но фиксируется в UI явным статусом «без триггеров — не появится в анкете»

**Связь с ERD:**

• Типовая работа — сущность справочника Атрибуты: ИД UUID, название, тип арх компонента стримаисполнителя у самой работы нет; стрим — это разрез для условий, коэффициентов и норм

• Условия типовых работ — список условий вида параметр, значение с привязкой к работа, тип арх компонента, стримисполнитель Один шаблон работы может срабатывать по разным условиям у разных стримисполнителей

• Параметры трудоёмкости — коэффициенты на комбинацию работа, параметр, значение, стримисполнитель Используются как множители в формуле

• Нормы трудозатрат — список значений нормы по комбинации работа, стримисполнитель с историчностью даты начала и окончания действия На дату расчёта анкеты выбирается актуальная норма

• Параметры и значения параметров — глобальные справочники, на которые ссылаются условия и коэффициенты Значения хранятся в JSON с историчностью и порядком сортировки

• Формула и округление — часть «Файла конфигурации» Версии шаблона Редактируются на этом же экране; при сохранении могут порождать новую минорную версию шаблона правило версионирования вынесено в отдельную спецификацию

Итоговое значение трудозатрат по работе для версии анкеты = округлить вычислить формула норматрудозатрат, коэфповыбраннымзначениямпараметров  , режим, шаг

**61 Backend**

**№**

**Описание**

**1**

**API на чтение справочника типовых работ: с фильтрацией по типу архитектурного компонента, стримисполнителю и пагинацией**

---

**2**

**API на карточку работы: возвращает работу с разрезом по выбранному стриму**

**3**

**API на изменение: payload содержит поля работы и/или массивы с указанием стрима Каждое поле валидируется отдельно, бэкенд возвращает массив ошибок с указанием пути**

**4**

**Валидация name: 1…255 после ввода**

**5**

**Валидация norms: каждая запись —  stream, normValue, validFrom, validTo?  normValue ≥ 0 decimal до 2 знаков validFrom — обязательна; validTo — опциональна, при наличии > validFrom Периоды одной работа, стрим не должны пересекаться На дату расчёта анкеты для работа, стрим должна быть ровно одна действующая запись — инвариант проверяется при сохранении**

**6**

**Валидация rules условий: каждая запись —  stream, archComponentType, paramId, valueId, operator  paramId должен ссылаться на действующую запись справочника «Параметры»; valueId — на действующее значение из «Значения параметров» для paramId operator — из словаря, для нечисловых значений допустимы только = и ≠**

**7**

**Валидация laborCoefficients: каждая запись —  stream, paramId, valueId, coefficient  coefficient ≥ 0 Уникальность по тройке stream, paramId, valueId в пределах одной работы**

**8**

**Валидация formula: парсер выражения над токенами  N норма, PparamId коэф параметра, число, оператор −×÷, скобки  PparamId допустим только если paramId присутствует в laborCoefficients работы При нарушении — ошибка с указанием позиции в исходной строке формулы**

**9**

**Валидация rounding:  mode ∈ CEIL, FLOOR, ROUND, NONE, step ; step обязателен и в 00001; 1000, если mode ≠ NONE; при mode = NONE step игнорируется и в payload может отсутствовать**

**10**

**Расчёт превью «POST /api/v1/works/id/preview»: вход —  stream, atDate, answers:  paramId: valueId   Сервер выбирает действующую на atDate норму, действующие значения параметров и коэффициенты, выполняет подстановку в формулу, применяет округление и возвращает  formulaSymbolic, formulaExpanded, result  или ошибку с указанием причины**

**11**

**Удаление работы «DELETE /api/v1/works/id»: каскадно удаляет связанные нормы, условия и коэффициенты в справочной части; перед удалением возвращает информацию о версиях анкеты, где работа уже учтена 409 Conflict с телом  usedInQuestionnaireVersions:  , чтобы фронт мог запросить подтверждение**

**12**

**Логика «работа подставляется в анкету только при срабатывании всех её условий» реализуется в сервисе расчёта Версии анкеты Работы с пустым массивом rules для работа, стрим исключаются из расчёта соответствует правилу из контекста**

**13**

**Версионирование шаблона при изменении формулы или округления: «PATCH /api/v1/works/id» возвращает 409 Conflict с кодом FORMULALOCKED, если изменения формулы/округления приходят на работу, формула которой используется в опубликованной Версии шаблона Фронт инициирует создание новой минорной версии шаблона отдельным запросом и повторяет PATCH**
