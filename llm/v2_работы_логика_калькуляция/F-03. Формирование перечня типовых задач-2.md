<a id="header-1"></a>__ 1\. Описание пользовательской истории__

__Я как__

__Архитектор данных / Офицер данных / Администратор смарт\-анкеты \(пользователь с ролью «Архитектор смарт\-анкеты»\)__

__Хочу__

__Иметь экран «Типовые работы», на котором для каждой работы из справочника настраиваются триггеры появления, коэффициенты параметров трудоёмкости \(в разрезе стрим\-исполнителя\), нормы трудозатрат \(с историчностью и стрим\-исполнителем\) и формула расчёта итогового значения с правилами округления__

__Для того, чтобы__

__Поддерживать справочник типовых работ и конфигурацию формул в версии шаблона анкеты без участия разработчика; гарантировать, что в анкету попадают только те работы, у которых сработали условия\-триггеры__

<a id="header-2"></a>__2\. Контекст__

__Смарт\-анкета__ — конфигуратор оценки трудозатрат по типовым работам в разрезе типов архитектурных компонентов \(Система\-источник, Объект / Витрина данных, Процесс обработки данных, Модель, Модельный сервис\) и стримов\-исполнителей\.

Раздел «Логика» → «Типовые работы» — экран администрирования справочника типовых работ и их конфигурации в редактируемой версии шаблона анкеты\.

На текущий момент в справочнике порядка 148 работ\. В UI группируются по типу архитектурного компонента\.

__Ключевое правило:__

• Типовая работа автоматически подставляется в анкету только при срабатывании всех условий\-триггеров\. Триггер — это набор из одного или более одновременно выполняемых условий \(объединение логическим «И»\)\.

• Работа без триггеров в анкету не попадает и в расчёте не участвует\. Такое состояние допустимо как промежуточное \(черновик\), но фиксируется в UI явным статусом «без триггеров — не появится в анкете»\.

__Связь с ERD\):__

• Типовая работа — сущность справочника\. Атрибуты: ИД \(UUID\), название, тип арх\. компонента\. стрима\-исполнителя у самой работы нет; стрим — это разрез для условий, коэффициентов и норм\.

• Условия типовых работ — список условий вида \(параметр, значение\) с привязкой к \(работа, тип арх\. компонента, стрим\-исполнитель\)\. Один шаблон работы может срабатывать по разным условиям у разных стрим\-исполнителей\.

• Параметры трудоёмкости — коэффициенты на комбинацию \(работа, параметр, значение, стрим\-исполнитель\)\. Используются как множители в формуле\.

• Нормы трудозатрат — список значений нормы по комбинации \(работа, стрим\-исполнитель\) с историчностью \(даты начала и окончания действия\)\. На дату расчёта анкеты выбирается актуальная норма\.

• Параметры и значения параметров — глобальные справочники, на которые ссылаются условия и коэффициенты\. Значения хранятся в JSON с историчностью и порядком сортировки\.

• Формула и округление — часть «Файла конфигурации» Версии шаблона\. Редактируются на этом же экране; при сохранении могут порождать новую минорную версию шаблона \(правило версионирования вынесено в отдельную спецификацию\)\.

Итоговое значение трудозатрат по работе для версии анкеты = округлить\( вычислить\( формула\( норма\_трудозатрат, коэф\.\_по\_выбранным\_значениям\_параметров \) \), режим, шаг \)\.

__4__

__Список норм по работе__

__Минимум 1 запись для каждой комбинации \(работа, стрим\-исполнитель\), участвующей в расчёте__

__17__

__Список параметров трудоёмкости__

__Условно \(0…N\)__

__Список параметров, влияющих на расчёт работы через формулу\.__

__Каждый элемент — параметр \+ словарь коэффициентов на каждое его значение\.__

__Пусто; либо 1\+ параметров__

__18__

__Параметр трудоёмкости — ссылка на параметр__

__Всегда \(внутри элемента\)__

__Параметр выбирается из того же справочника, что и в условиях\. Один и тот же параметр не может быть добавлен в список параметров трудоёмкости работы для одного стрим\-исполнителя дважды\.__

__ИД параметра, ещё не добавленного для \(работа, стрим\)__

__Повторный выбор уже добавленного параметра__

__Сообщение: «Параметр уже добавлен в список параметров трудоёмкости работы для текущего стрим\-исполнителя»\.__

__19__

__Коэффициенты по значениям параметра__

__Всегда \(внутри элемента\)__

__Для каждого действующего значения параметра — отдельный коэффициент\. Коэффициент — неотрицательное дробное число \(до двух знаков после точки\)\. Дефолтное значение — 1\. Текущее значение, подставляемое из активной версии анкеты, подсвечивается в превью\.__

__0\.5; 1; 1\.25; 3__

__−0\.5; «abc»; пусто__

__Сохранение строки коэффициента блокируется\. Сообщение: «Коэффициент должен быть неотрицательным числом»\.__

__—__

__—__

__Формула \(выражение\)__

__Всегда__

__6\. Работы в разрезе спецификации__

__6\.1 Backend__

__№__

__Описание__

__1__

__API на чтение справочника типовых работ: с фильтрацией по типу архитектурного компонента, стрим\-исполнителю и пагинацией\.__

__ __

__2__

__API на карточку работы: возвращает работу с разрезом по выбранному стриму__

__3__

__API на изменение: payload содержит поля работы и/или массивы с указанием стрима\. Каждое поле валидируется отдельно, бэкенд возвращает массив ошибок с указанием пути\.__

__4__

__Валидация name: 1…255 после ввода__

__5__

__Валидация norms: каждая запись — \{ stream, normValue, validFrom, validTo? \}\. normValue ≥ 0 \(decimal до 2 знаков\)\. validFrom — обязательна; validTo — опциональна, при наличии > validFrom\. Периоды одной \(работа, стрим\) не должны пересекаться\. На дату расчёта анкеты для \(работа, стрим\) должна быть ровно одна действующая запись — инвариант проверяется при сохранении\.__

__6__

__Валидация rules \(условий\): каждая запись — \{ stream, archComponentType, paramId, valueId, operator \}\. paramId должен ссылаться на действующую запись справочника «Параметры»; valueId — на действующее значение из «Значения параметров» для paramId\. operator — из словаря, для нечисловых значений допустимы только = и ≠\.__

__7__

__Валидация laborCoefficients: каждая запись — \{ stream, paramId, valueId, coefficient \}\. coefficient ≥ 0\. Уникальность по тройке \(stream, paramId, valueId\) в пределах одной работы\.__

__8__

__Валидация formula: парсер выражения над токенами \{ N \(норма\), P\(paramId\) \(коэф\. параметра\), число, оператор \+−×÷, скобки \}\. P\(paramId\) допустим только если paramId присутствует в laborCoefficients работы\. При нарушении — ошибка с указанием позиции в исходной строке формулы\.__

__9__

__Валидация rounding: \{ mode ∈ \{CEIL, FLOOR, ROUND, NONE\}, step \}; step обязателен и в \[0\.0001; 1000\], если mode ≠ NONE; при mode = NONE step игнорируется и в payload может отсутствовать\.__

__10__

__Расчёт превью «POST /api/v1/works/\{id\}/preview»: вход — \{ stream, atDate, answers: \{ paramId: valueId \} \}\. Сервер выбирает действующую на atDate норму, действующие значения параметров и коэффициенты, выполняет подстановку в формулу, применяет округление и возвращает \{ formulaSymbolic, formulaExpanded, result \} или ошибку с указанием причины\.__

__11__

__Удаление работы «DELETE /api/v1/works/\{id\}»: каскадно удаляет связанные нормы, условия и коэффициенты в справочной части; перед удалением возвращает информацию о версиях анкеты, где работа уже учтена \(409 Conflict с телом \{ usedInQuestionnaireVersions: \[\.\.\.\] \}\), чтобы фронт мог запросить подтверждение\.__

__12__

__Логика «работа подставляется в анкету только при срабатывании всех её условий» реализуется в сервисе расчёта Версии анкеты\. Работы с пустым массивом rules для \(работа, стрим\) исключаются из расчёта \(соответствует правилу из контекста\)\.__

__13__

__Версионирование шаблона при изменении формулы или округления: «PATCH /api/v1/works/\{id\}» возвращает 409 Conflict с кодом FORMULA\_LOCKED, если изменения формулы/округления приходят на работу, формула которой используется в опубликованной Версии шаблона\. Фронт инициирует создание новой минорной версии шаблона отдельным запросом и повторяет PATCH\.__

__№__

__Описание__

__1__

__Реализовать экран двухпанельным layout: слева — список работ \(виртуализованный, т\.к\. ~148\+ элементов\), справа — карточка выбранной работы\.__

__2__

__5__

__Шапка карточки работы — селектор стрим\-исполнителя\. При смене стрима блоки «Нормы», «Условия», «Параметры трудоёмкости» перерисовываются по соответствующему разрезу\. Состояние выбранного стрима запоминается на сессию пользователя \(per\-user\-per\-work\) и подставляется при следующем открытии карточки\.__

__6__

__Карточка работы — стек блоков, каждый — отдельный компонент: NormsEditor \(список с историчностью\), RulesEditor, LaborCoefficientsEditor, FormulaEditor, RoundingEditor, PreviewCard\.__

__7__

__NormsEditor: таблица записей со столбцами «Норма», «Дата начала», «Дата окончания», действиями\. Валидация перекрытия периодов выполняется на клиенте \(быстрая обратная связь\) и подтверждается ответом бэкенда\.__

__8__

__RulesEditor: список условий в виде grid \(параметр, оператор, значение, действие удалить\)\. Над списком — статус\-плашка триггера\. Кнопка «\+ Условие» в шапке блока; недоступна, если в шапке карточки не выбран стрим\.__

__9__

__LaborCoefficientsEditor: на каждый параметр трудоёмкости — раскрывающаяся секция с таблицей коэффициентов по значениям\. Текущее значение из последнего черновика расчёта анкеты выделяется\.__

__10__

__FormulaEditor: два режима — «Визуально» \(drag\-and\-drop чипов\) и «Вручную» \(текст с парсером\)\. Парсер выражений — общий с бэкендом \(через WASM либо продублирован на JS\)\. Кнопка «Коэф\. параметра» в палитре отключена, если у работы нет ни одного параметра трудоёмкости\. При попытке отредактировать формулу в опубликованной версии шаблона — модалка о создании минорной версии\.__

__11__

__RoundingEditor: выбор режима и шага\. При режиме «Без округления» поле шага становится недоступным\.__

__12__

__PreviewCard: пересчёт на клиенте при любом изменении \(дебаунс ~100 мс\)\. Кнопка «Сверить с сервером» — отправляет запрос POST /preview и сравнивает результаты; при расхождении — предупреждение с возможностью открыть отладочный вывод обоих расчётов\.__

__13__

__Автосохранение: PATCH /api/v1/works/\{id\} с дебаунсом ~600 мс\. Индикатор статуса в шапке карточки\. При ошибке — уведомление \+ действие «Повторить»\. Локальный буфер на IndexedDB на случай сетевых сбоев\.__

__14__

__Числовые поля принимают на ввод как «\.», так и «,», на отправку нормализуют в «\.»\. Поля дат — стандартный datepicker с форматом ДД\.ММ\.ГГГГ; вводимое значение валидируется на формат и на логическую корректность периода\.__

__15__

__Все строки UI вынесены в локали \(ru\-RU — основной язык\)\. Подсказки к параметрам подтягиваются из атрибута «Описание \(подсказка\)» сущности «Параметры»\.__
