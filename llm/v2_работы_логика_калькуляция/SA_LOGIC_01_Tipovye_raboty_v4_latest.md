__Для того, чтобы__

# __2\. Контекст__

Смарт\-анкета — конфигуратор оценки трудозатрат по типовым работам в разрезе типов архитектурных компонентов \(Система\-источник, Объект / Витрина данных, Процесс обработки данных, Модель, Модельный сервис\) и стримов\-исполнителей\.

Раздел __«Логика» → «Типовые работы»__ — экран администрирования справочника типовых работ и их конфигурации в редактируемой версии шаблона анкеты\. В UI работы группируются по типу архитектурного компонента\.

__ НОВОЕ __ __Парадигма «справочник \+ назначения»\.__ Типовая работа — запись общего справочника, содержащая только «реестровые» поля: название и тип архитектурного компонента\. Нормы трудозатрат, условия появления, параметры трудоёмкости и формула живут не на самой работе, а на сущности __«Назначение работы на область»__ — комбинации \(работа, тип арх\. компонента, стрим\-исполнитель\)\. У одной работы может быть несколько назначений на разные области \(стримы\); каждая область настраивается независимо\.

__Ключевые правила:__

- Типовая работа автоматически подставляется в анкету __только при срабатывании всех условий\-триггеров__ назначения, актуального для текущего стрима\-исполнителя\. Триггер — это набор из одного или более одновременно выполняемых условий \(объединение логическим «И»\)\.
- __Работа без триггеров в анкету не попадает__ и в расчёте не участвует\. Такое состояние допустимо как промежуточное \(черновик\), но фиксируется в UI явным статусом «без триггеров — не появится в анкете»\.
- Если у работы есть триггеры, но при текущих ответах в черновике расчёта анкеты они не выполнены, статус работы — __«скрыта»__\. Работа есть в шаблоне, но в данную версию расчёта анкеты не попадает\.
- __ НОВОЕ __ Условие появления может быть как простым «параметр __=__ значение», так и __«одно из значений» \(anyof\)__ — параметр \+ множество значений; работа появляется, если ответ пользователя ∈ множеству\. Внутри множества — логическое «ИЛИ»; между разными условиями работы — по\-прежнему «И»\.
- __Параметры трудоёмкости__ — коэффициенты на конкретное значение параметра \(вид «по значениям»\)\. __ НОВОЕ __ Дополнительный вид — __any\-of__: коэффициент применяется к множеству значений \(коэф\. «on» — если ответ ∈ множеству, коэф\. «off» — иначе\)\. Используется как множитель или слагаемое в формуле работы\.
- __Нормы трудозатрат__ — список значений нормы по комбинации \(работа, стрим\-исполнитель\) с историчностью \(даты начала и окончания действия\)\. На дату расчёта анкеты выбирается актуальная норма\.
- __Формула работы__ собирается из __членов \(terms\)__ трёх видов: __множитель__ \(умножается на накопленный результат\), __слагаемое__ \(добавляется к накопленному результату\), __транзитивная ссылка__ \(значение целиком копируется из другой работы — норма и собственные коэффициенты не применяются; циклы запрещены\)\.
- У каждого члена\-множителя и члена\-слагаемого может быть набор __факторов__ — ссылок на параметры трудоёмкости работы\. Значение члена в расчёте = базовое значение × произведение коэффициентов выбранных в анкете значений параметров\.
- __«Базовый норматив работы»__ — встроенный член\-множитель, ссылается на действующую запись нормы трудозатрат для \(работа, стрим\)\. Этот член присутствует в формуле всегда, удалить нельзя\.
- __Параметры и значения параметров__ — глобальные справочники\. У параметра есть явный тип значений: число, строка, «да/нет», справочник, строка\-справочник\. От типа зависит UI ввода значений в условиях и коэффициентах\.
- __Формула и округление__ хранятся в Файле конфигурации Версии шаблона\. Изменения структуры порождают новую __мажорную__ версию шаблона; изменения формулы — __минорную__\. У версии шаблона есть статус: Черновик / Опубликована / Архив / Активная\.

Типовая работа \(запись каталога\)

Назначение работы на область

ID назначения \(PK\); ID работы \(FK\); Тип архитектурного компонента; Стрим\-исполнитель; Признак активности

Привязка работы к конкретной области \(комбинация типа арх\. компонента и стрима\-исполнителя\)\. Условия типовых работ

ID назначения \(FK\); ID параметра \(FK\); Тип условия \(=, ≠, ∈, ∉, >, <, ≥, ≤\); Множество ID значений \(JSON\); Порядок

Триггер появления работы в анкете\. Все условия одного назначения объединяются логическим «И»\. Для типов условия =, ≠, >, <, ≥, ≤ множество содержит ровно один ID значения; для ∈ \(anyof\) и ∉ \(none of\) — N значений \(внутри множества — логическое «ИЛИ»\)\. Если у назначения нет ни одного условия — работа в анкету не подставляется\.

Параметры трудоёмкости

ID назначения \(FK\); ID параметра \(FK\); Вид \(по значениям / any\-of\); Коэффициенты по значениям \(JSON\); Коэффициенты on / off \(для any\-of\)

Параметр, влияющий на расчёт работы через факторы членов формулы\. Вид «по значениям» — отдельный коэффициент на каждое действующее значение параметра\. Вид «any\-of» — два коэффициента: «on» применяется, если ответ ∈ множеству выбранных значений; «off» — иначе\. Свой набор для каждого назначения\.

Нормы трудозатрат

ID назначения \(FK\); Норма трудозатрат; Дата начала действия; Дата окончания действия

Базовое значение нормы \(чел\.\-дн\.\) с историчностью\. Привязано к назначению \(а значит — к комбинации работы и стрима\)\. На дату расчёта анкеты выбирается норма, попадающая в действующий период\. Дата окончания может быть пустой — норма действует «до отмены»\.

Параметры

ID параметра \(UUID, PK\); Имя параметра; Описание \(подсказка\); Тип значения \(число / строка / да\-нет / справочник / строка\-справочник\); Версия

Глобальный справочник параметров\. Ссылается на справочник «Значения параметров»\. Тип значения определяет UI ввода и состав допустимых операторов в условиях\. Версия меняется при изменении состава или семантики значений\.

Значения параметров

ID параметра \(FK\); ID значения \(PK, JSON\); Значение \(JSON\); Порядок сортировки; Дата начала действия; Дата окончания действия

Возможные значения параметра\. Историзованы; в один момент времени для параметра действует подмножество значений с непросроченной датой окончания\.

Член формулы \(Term\)

ID члена \(PK\); ID назначения \(FK\); Вид члена \(множитель / слагаемое / транзитивная ссылка\); Название члена; Признак «базовый» \(встроенный «Базовый норматив работы»\); ID назначения\-источника \(FK, только для транзитивной ссылки\); Порядок

Член формулы работы\. Множитель умножается на накопленный результат, слагаемое — прибавляется, транзитивная ссылка целиком копирует значение из другого назначения \(норма и факторы текущего назначения при этом не применяются\)\. У каждого назначения есть ровно один встроенный член «Базовый норматив работы» с признаком «базовый»; удалить нельзя\.

Фактор члена \(Factor\)

ID фактора \(PK\); ID члена \(FK\); ID параметра трудоёмкости \(FK\); Порядок

Привязка параметра трудоёмкости к конкретному члену формулы\. Коэффициент выбирается по правилам параметра трудоёмкости \(см\. атрибут «Вид»\): для «по значениям» — по выбранному в анкете значению; для «any\-of» — on или off в зависимости от того, попадает ли ответ в множество\. Фактор не имеет смысла для членов вида «транзитивная ссылка»\.

Шаблон

ID Шаблона \(PK\); Название шаблона; Статус

Шаблон смарт\-анкеты — структура \+ формулы\. Имеет 1…N версий\. Изменения структуры — мажорная версия, изменения формулы — минорная\.

Версия шаблона

ID версии шаблона \(PK\); ID Шаблона \(FK\); Вид версии \(мажор / минор\); Статус \(Черновик / Опубликована / Архив / Активная\); Дата публикации; Файл конфигурации

«Файл конфигурации» содержит структуру СА и формулы для типовых работ, включаемых в шаблон, а также правила округления\. «Активная» статусом отмечена ровно одна версия шаблона в каждый момент времени\.

Анкета

ID Анкеты \(PK\); ID Модельного сервиса; Заказчик; Стрим\-исполнитель

Калькуляция трудозатрат для конкретного объекта работ\. Имеет 1…N версий; активна последняя\.

Версия анкеты

ID Версии шаблона \(FK\); ID Анкеты \(FK\); RFD; Файл со значениями; Автор; Статус

Конкретный расчёт\. Все версии анкеты строятся на одной версии шаблона\. Версии могут отличаться значениями параметров и/или версиями справочников\.

Дополнительные индикаторы: статус назначения работы на стрим \(«не назначена» / «свободна» / «уже на N схемах»\), статус видимости работы при текущих ответах анкеты \(«появляется» / «скрыта» / «без триггеров»\), краткие бейджи «коэф\.: множитель / слагаемое / без коэф\.» и режима округления\.

Селектор стрима меняет видимые блоки: условия, коэффициенты параметров и нормы отображаются для выбранного стрима\. При смене стрима блоки перерисовываются без перезагрузки карточки\. Выбор стрима запоминается на сессию пользователя\.

5

Тело карточки — блоки

«Нормы трудозатрат», «Условия появления работы», «Параметры трудоёмкости», «Конструктор формулы» \(виды членов: множитель / слагаемое / транзитивная ссылка\), «Округление», «Превью результата»\.

Все блоки редактируются построчно\. Превью пересчитывается мгновенно\.

6

Пустое состояние области

Когда у выбранной области \(тип арх\. компонента \+ стрим\) ещё нет ни одного назначения работы — в центре экрана отображается информационное сообщение «Типовые работы хранятся в общем справочнике\. Выберите нужные и назначьте на эту область — у каждой работы будут свои нормативы и логика именно для этого стрима» и два действия: «Добавить из каталога» и «\+ Новая типовая работа»\.

Действие «Добавить из каталога» открывает панель выбора работ из общего справочника с поиском\. Действие «\+ Новая типовая работа» открывает модалку создания \(см\. ниже\)\.

7

Модалка «Новая типовая работа» / «Изменить типовую работу»

Единая модалка с двумя режимами\. В режиме создания заголовок «Новая типовая работа», кнопка «Создать работу», нижняя подсказка «Работа добавится в выбранный архитектурный компонент»; видны поля «Название», «Архитектурный компонент», «Стрим\-исполнитель», «Стартовый норматив, чел\.\-дн\.»\. В режиме редактирования заголовок «Изменить типовую работу», кнопка «Сохранить», нижняя подсказка «Изменения применяются сразу к справочнику»; видны только «Название» и «Архитектурный компонент»; стрим\-исполнитель помечается «\(рекомендация\)», стартовый норматив скрыт\.

Модалка вызывается из шапки каталога \(«\+ Новая типовая работа»\), из пустого состояния области и через действие «изменить» в карточке записи каталога\. Сохранение в режиме создания добавляет запись в каталог, создаёт назначение на \(выбранный арх\. компонент, выбранный стрим\) и стартовую норму\. Сохранение в режиме редактирования меняет только реестровые поля каталога — назначения и нормы не затрагиваются\.

Если все доступные параметры уже добавлены — кнопка недоступна с подсказкой «Все параметры этого справочника уже добавлены»\.

25

Действие «удалить параметр»

—

Удаляет элемент из списка вместе со всеми коэффициентами\. Подтверждение запрашивается, если параметр используется как фактор хотя бы одного члена формулы\.

—

—

Модалка: «Параметр используется как фактор членов формулы\. Удалить вместе со ссылками или отменить?»\. Опции: «Удалить» / «Отмена»\.

Контекст хранения

—

Формула, набор членов и режим округления хранятся в Файле конфигурации Версии шаблона\. Изменение формулы порождает новую минорную версию шаблона\.

—

—

При попытке изменить формулу в опубликованной версии шаблона — модалка «Открыть редактирование в новой минорной версии шаблона?»\. Опции: «Создать минорную версию» / «Отмена»\.

27

Формула как список членов \(terms\)

Всегда

Формула работы — упорядоченный список членов\. Каждый член — один из трёх видов: множитель / слагаемое / транзитивная ссылка \(см\. отдельные правила ниже\)\. Накопленный результат формируется последовательно: множители перемножаются между собой; слагаемые прибавляются к произведению множителей; транзитивная ссылка целиком замещает значение работы \(см\. правило 30\)\. Минимальный состав формулы — один встроенный член «Базовый норматив работы» \(см\. правило 28\)\.

1\+ корректных членов с встроенным «Базовый норматив работы»

Удалён встроенный «Базовый норматив работы»; есть транзитивная ссылка одновременно с другими членами

Сохранение блокируется\. Сообщения: «Член “Базовый норматив работы” обязателен и не может быть удалён» / «Транзитивная ссылка не сочетается с другими членами формулы — оставьте только её или замените на множитель/слагаемое»\.

28

Встроенный член «Базовый норматив работы»

Всегда

У каждой работы в формуле присутствует ровно один встроенный член\-множитель «Базовый норматив работы»\. Его базовое значение = действующая на дату расчёта норма трудозатрат для \(работа, стрим\)\. Удалить нельзя; можно изменить только состав факторов \(см\. правило 31\)\.

—

Попытка удаления

Действие «удалить» у этого члена недоступно с подсказкой «Базовый норматив работы — встроенный член формулы»\.

29

Член\-множитель / член\-слагаемое

—

Добавляются пользователем в дополнение к базовому\. Множитель — название члена \+ 0…N факторов; в расчёте даёт значение «базовое значение × произведение коэффициентов выбранных в анкете значений параметров факторов»\. Слагаемое — то же, но прибавляется к накопленному результату\. Базовое значение задаётся вручную дробным неотрицательным числом \(по умолчанию 1\)\.

Корректный член с непустым названием и неотрицательным базовым значением

Базовое значение отрицательное / нечисловое / пустое; пустое название

Сохранение члена блокируется\. Сообщение: «Заполните название и неотрицательное базовое значение члена»\.

30

Член — транзитивная ссылка

—

Особый вид члена: значение работы целиком копируется из другого члена\-работы по ссылке\. Норма и собственные факторы работы при этом не применяются\. В рамках одной формулы такой член должен быть единственным\. Циклы транзитивных ссылок запрещены: добавление ссылки, замыкающей цикл, отклоняется\. На UI выбор работы — через поиск по справочнику с подсказками\.

Ссылка на существующую работу, не образующая цикл

Ссылка на удалённую работу; ссылка, замыкающая цикл; одновременное присутствие с другими членами

Сообщения: «Работа\-источник не найдена» / «Транзитивная ссылка приводит к циклу через работы <список>» / «Транзитивная ссылка должна быть единственным членом формулы»\.

31

Факторы члена \(Factor\)

Условно \(0…N\)

Для членов вида «множитель» и «слагаемое» — список факторов\. Фактор — ссылка на параметр из блока «Параметры трудоёмкости» работы \(для текущего стрима\)\. Один и тот же параметр не может быть фактором одного члена дважды \(между разными членами повторение допустимо\)\.

0\+ корректных факторов

Параметр\-фактор отсутствует в блоке «Параметры трудоёмкости» текущего стрима; повтор внутри одного члена

Сообщения: «Параметр не добавлен в блок “Параметры трудоёмкости” текущего стрима» / «Параметр уже используется как фактор этого члена»\.

32

Палитра действий

—

Кнопки: «\+ Множитель», «\+ Слагаемое», «\+ Транзитивная ссылка»\. Для каждого добавленного члена — действия «\+ Фактор» \(для множителя/слагаемого\), «удалить» \(кроме встроенного\), «переупорядочить» \(drag\-and\-drop\)\.

—

—

«\+ Транзитивная ссылка» недоступна, если в формуле уже есть другие члены кроме встроенного «Базовый норматив работы», и подсвечивается подсказкой о правиле единственности\.

33

Бейдж типа коэффициентов работы в шапке

Авто \(вычисляется\)

Краткая сводка о видах членов в формуле работы: «коэф\.: множитель» — есть только множители \(помимо базового\); «коэф\.: слагаемое» — есть только слагаемые; «коэф\.: множитель \+ слагаемое» — есть и те, и другие; «коэф\.: транзитивная» — формула состоит из транзитивной ссылки; «без коэф\.» — кроме базового норматива других членов нет\.

—

—

Бейдж информационный, действия не требуются\.

__ОКРУГЛЕНИЕ — часть «Файла конфигурации» Версии шаблона__

34

Режим округления

Всегда

Один из четырёх режимов: «вверх», «вниз», «математическое», «без округления»\. По умолчанию для новой работы — «вверх»\.

Один из четырёх режимов

Значение вне словаря

Сообщение: «Выберите режим округления»\.

35

Шаг округления

Условно

Дробное положительное число \(до 4 знаков после точки\)\. Допустимый диапазон — \[0\.0001; 1000\]\. По умолчанию — 0\.1\. Поле игнорируется \(становится недоступным\), если режим — «без округления»\.

Положительное число в допустимом диапазоне

Ноль; отрицательное число; нечисловое значение; число вне диапазона

Сообщение: «Шаг округления должен быть положительным числом в допустимом диапазоне»\.

36

Карточка превью

—

Поле «Название» в модалке

Поле «Архитектурный компонент» в модалке

Поле «Стрим\-исполнитель» в модалке

Условно \(по режиму\)

В режиме создания — стрим из доступных

В режиме создания — стрим не выбран

Отрицательное число; нечисловое значение; пустое значение

Действие «Создать работу» \(режим создания\)

Действие «Сохранить» \(режим редактирования\)

—

При нажатии: \(а\) сохраняются изменения «реестровых» полей записи каталога \(название, архитектурный компонент\); \(б\) изменения применяются сразу к справочнику — другие назначения работы продолжают использовать обновлённые реестровые поля автоматически; \(в\) назначения, нормы и логика не затрагиваются\.

45

Пустое состояние области

—

Когда для выбранной области \(тип арх\. компонента \+ стрим\) нет ни одного назначения работы — в центре экрана отображается сообщение «Типовые работы хранятся в общем справочнике\. Выберите нужные и назначьте на эту область — у каждой работы будут свои нормативы и логика именно для этого стрима» и действия «Добавить из каталога» и «\+ Новая типовая работа»\.

—

46

Назначение работы на область из каталога

—

Пользователь выбирает работу в каталоге; в открывающейся панели подтверждает добавление в текущую область \(тип арх\. компонента \+ стрим\)\. Если у работы уже есть назначение на эту область — кнопка добавления недоступна с подсказкой «Уже добавлено в эту область»\. После подтверждения создаётся пустое назначение \(без норм, условий, параметров\); пользователь переходит на карточку назначения\.

—

—

Сообщение в панели: «Работа добавлена в область <название>\. Заполните норму трудозатрат и условия появления»\.

47

Удаление работы из каталога

—

Доступно из контекстного меню записи каталога\. Запрашивается подтверждение\. Удаляются: запись каталога, все её назначения, все нормы / условия / параметры / члены формулы / факторы этих назначений\. Транзитивные ссылки из других работ на любое назначение удаляемой работы — отклоняют операцию до их разрешения\.

—

—

Если работа учтена в опубликованных версиях анкеты или на её назначения ссылаются транзитивные ссылки — модалка с подтверждением каскадного удаления и списком зависимых объектов\.

48

Снятие назначения с области

—

Доступно из карточки назначения \(действие «снять с этой области»\)\. Запрашивается подтверждение\. Удаляются нормы, условия, параметры, члены формулы, факторы только этого назначения; сама запись каталога и её назначения на другие области остаются неизменными\.

—

—

Если назначение учтено в опубликованных версиях анкеты — модалка с предупреждением: «Назначение учтено в версиях анкеты <список>\. Снять только из черновика?»\. Опции: «Снять» / «Отмена»\.

—

—

Изменения в карточке назначения отправляются на бэкенд\. В шапке карточки — индикатор статуса: «Сохранено» / «Сохранение…» / «Ошибка сохранения»\.

Сетевой сбой

# __6\. Работы в разрезе спецификации__

## __6\.1 Backend__

__№__

__Описание__

1

Разделение API на «каталог» \(записи справочника типовых работ\) и «назначения работ на области»\. Эндпоинты каталога управляют только реестровыми полями \(название, тип арх\. компонента\); эндпоинты назначений — нормами, условиями, параметрами трудоёмкости, формулой и округлением\.

2

Каталог: «GET /api/v1/catalog/works» — список записей справочника с фильтрацией по типу арх\. компонента и поиском по названию\. У каждой записи — сводка по назначениям \(количество назначений по областям\) для отображения статуса\.

3

Каталог: «POST /api/v1/catalog/works» — создание новой записи справочника\. Принимает реестровые поля и опционально первое назначение со стартовым нормативом\. Атомарная транзакция: каталоговая запись \+ назначение \+ первая запись нормы\. При успехе возвращает ID записи и ID назначения\.

4

Каталог: «PATCH /api/v1/catalog/works/\{id\}» — изменение реестровых полей\. Меняет только название и тип арх\. компонента; не затрагивает назначения и связанные с ними нормы/условия/параметры/формулу\.

5

Каталог: «DELETE /api/v1/catalog/works/\{id\}» — каскадное удаление записи с проверкой зависимостей\. Удаляет все назначения работы и связанные с ними сущности\. Перед удалением проверяет наличие транзитивных ссылок и использование в опубликованных версиях анкеты; при наличии — 409 Conflict с описанием зависимостей\.

6

Назначения: «GET /api/v1/assignments?work=\{workId\}&areaType=\{type\}&stream=\{stream\}» — получить назначение по комбинации \(работа \+ область\)\. Возвращает полную конфигурацию: нормы, условия, параметры трудоёмкости, формулу, округление\.

7

Назначения: «POST /api/v1/assignments» — добавление работы из каталога в область \(без стартового норматива\)\. Возвращает ID назначения\. Если назначение уже существует — 409 Conflict\.

8

Назначения: «PATCH /api/v1/assignments/\{id\}» — изменение конфигурации \(нормы, условия, параметры трудоёмкости, формула, округление\)\. Каждое поле валидируется отдельно; бэкенд возвращает массив ошибок с указанием пути\.

9

Назначения: «DELETE /api/v1/assignments/\{id\}» — снятие назначения с области\. Каскадно удаляет нормы, условия, параметры, члены формулы и факторы только данного назначения\. Запись каталога и другие назначения остаются\.

10

Валидация условий: каждое условие — \{ назначение, параметр, тип условия, множество ID значений, порядок \}\. Для типов = / ≠ / > / < / ≥ / ≤ множество содержит ровно один ID значения; для ∈ / ∉ — ≥ 1 значения\. Состав допустимых типов условия зависит от типа значений параметра\.

11

Валидация параметров трудоёмкости: каждая запись — \{ назначение, параметр, вид, коэффициенты \}\. Вид = «по значениям» — коэффициенты словарём по ID значений \(≥ 0 каждое\)\. Вид = «any\-of» — \{ множество ID значений \(≥ 1\), коэф\. on \(≥ 0\), коэф\. off \(≥ 0\) \}\. Уникальность по \(назначение, параметр\)\.

12

Валидация записей нормы: значение ≥ 0; дата начала — обязательна; дата окончания — опциональна, при наличии > даты начала; периоды одного назначения не должны пересекаться; на дату расчёта анкеты должна быть ровно одна действующая запись \(инвариант проверяется при сохранении\)\.

13

Валидация членов формулы \(terms\): у назначения должен быть ровно один встроенный член «Базовый норматив работы»\. Остальные члены — добавляемые пользователем множители, слагаемые или транзитивная ссылка \(взаимоисключающая с другими членами\)\. Базовое значение для множителя/слагаемого ≥ 0\. Каждый фактор члена ссылается на параметр трудоёмкости из того же назначения\.

14

Валидация транзитивной ссылки: ссылка указывает на существующее назначение\-источник\. При сохранении выполняется проверка отсутствия циклов транзитивных ссылок \(обход по графу transitive\-членов всех назначений\); цикл отклоняется с сообщением о пути цикла\.

15

Валидация округления: режим из словаря \{вверх, вниз, математическое, без округления\}; шаг обязателен и положительный, если режим ≠ «без округления»; при режиме «без округления» шаг игнорируется и может отсутствовать в payload\.

16

Расчёт превью: вход — \{ назначение, дата расчёта, ответы пользователя по параметрам \}\. Сервер выбирает действующую на дату норму, действующие значения параметров и коэффициенты \(учитывая вид «по значениям» / «any\-of»\), вычисляет каждый член формулы, агрегирует по правилам видов членов, применяет округление; возвращает символическую и развёрнутую запись формулы \+ итог или ошибку\.

17

Расчёт условий типа anyof: условие выполнено, если ответ пользователя ∈ множеству значений условия; для типа ∉ — обратно\. Внутри множества — логическое «ИЛИ», между разными условиями назначения — «И»\.

18

Логика «работа подставляется в анкету только при срабатывании всех её условий» — в сервисе расчёта Версии анкеты\. Назначения с пустым списком условий исключаются из расчёта\.

19

Версионирование шаблона при изменении формулы или округления: возвращается 409 Conflict с кодом FORMULA\_LOCKED, если изменения приходят на формулу/округление назначения, формула которого используется в опубликованной Версии шаблона\. Фронт инициирует создание новой минорной версии шаблона отдельным запросом\.

## __6\.2 Frontend__

__№__

__Описание__

1

Реализовать экран с двумя сценариями навигации: \(а\) через каталог записей справочника типовых работ — реестровая часть; \(б\) через карточку конкретного назначения работы на область — конфигурационная часть\.

2

Сегмент\-переключатель раздела «Типовые работы / Зависимости параметров» — состояние сохраняется в URL\.

3

Переключатель вида «Дерево / Таблица / Карточки» — в первой итерации реализовать только «Дерево»; «Таблица» и «Карточки» — заглушка «Будет реализовано позже»\.

4

В дереве работ: группа типа архитектурного компонента сворачивается/раскрывается; рядом с названием — счётчик работ\. Выбранная работа визуально выделена; рядом с каждой работой — набор информационных меток: статус видимости \(«появляется» / «скрыта» / «без триггеров»\) и статус назначения на стримы\.

5

Шапка карточки назначения работы — название работы, бейдж типа архитектурного компонента, бейдж стрима\-исполнителя \(для навигации между назначениями работы\), действие «изменить» \(открывает модалку редактирования реестровых полей каталога\) и набор информационных бейджей \(статус видимости, краткая сводка о видах членов формулы, краткая запись режима округления\)\.

6

Карточка назначения — стек блоков, каждый — отдельный компонент: редактор нормативов, редактор условий, редактор параметров трудоёмкости, редактор формулы \(с членами и факторами\), редактор округления, карточка предпросмотра\.

7

Пустое состояние области: компонент, отображающийся, когда для \(тип арх\. компонента \+ стрим\) нет ни одного назначения\. Содержит информационное сообщение и две кнопки: «Добавить из каталога» и «\+ Новая типовая работа»\.

8

Модалка «Новая типовая работа» / «Изменить типовую работу»: единый компонент с двумя режимами \(создание / редактирование\)\. В режиме создания показывает все поля \(название, арх\. компонент, стрим, стартовый норматив\); в режиме редактирования — только реестровые \(название \+ арх\. компонент\)\. Кнопка действия и тексты подсказок переключаются по режиму\. Валидация — на клиенте \+ подтверждение бэкендом; кнопка действия недоступна до прохождения клиентской валидации\.

9

Панель «Добавить из каталога»: поиск по названию \+ список записей справочника, не назначенных на текущую область\. Действие — добавление работы в область одним кликом \(создание пустого назначения\)\.

10

Редактор нормативов: таблица записей со столбцами «Норма», «Дата начала», «Дата окончания», действиями\. Валидация перекрытия периодов выполняется на клиенте \(быстрая обратная связь\) и подтверждается ответом бэкенда\.

11

Редактор триггеров \(условий\): список условий \(параметр, тип условия, значение\(я\), действие удалить\)\. Состав типов условия и UI ввода значения подбирается по типу значений параметра\. Для типов ∈ и ∉ ввод значения — мультивыбор чипами с отметками\. Над списком — статус\-плашка триггера\.

12

Редактор коэффициентов трудоёмкости: на каждый параметр трудоёмкости — раскрывающаяся секция с переключателем вида \(«по значениям» / «any\-of»\)\. Для вида «по значениям» — таблица коэффициентов по значениям\. Для вида «any\-of» — мультивыбор значений \+ два числовых поля «on» и «off»\. Текущее значение из последнего черновика расчёта анкеты выделяется\.

13

Редактор формулы: список членов \(terms\)\. Доступны действия «\+ Множитель», «\+ Слагаемое», «\+ Транзитивная ссылка»\. Для каждого добавленного члена \(кроме встроенного «Базовый норматив работы»\) — действия «удалить» и «переупорядочить»\. Для членов\-множителей/слагаемых — список факторов \(ссылок на параметры трудоёмкости назначения\) с действием «\+ Фактор»\. Для транзитивной ссылки — поиск назначения по справочнику с предупреждением при попытке выбора, образующего цикл\. При попытке отредактировать формулу в опубликованной версии шаблона — модалка о создании минорной версии\.

14

Редактор округления: выбор режима и шага\. При режиме «Без округления» поле шага становится недоступным\.

15

Превью: пересчёт на клиенте при любом изменении\. Развёрнутая запись формулы с подставленными значениями факторов по текущим ответам анкеты, с применённым округлением\. Кнопка «Сверить с сервером» — отправляет запрос расчёта на бэкенд и сравнивает результаты\.

16

Автосохранение\. Индикатор статуса в шапке карточки\. При ошибке — уведомление \+ действие «Повторить»\. Локальный буфер на случай сетевых сбоев\.

17

Числовые поля принимают на ввод как «\.», так и «,», на отправку нормализуют в «\.»\. Поля дат — стандартный datepicker с форматом ДД\.ММ\.ГГГГ; вводимое значение валидируется на формат и логическую корректность периода\.

18

Подсказки к параметрам подтягиваются из атрибута «Описание \(подсказка\)» сущности «Параметры»\. Подсказки в бейджах статусов — из расчётных правил \(например, для «скрыта» — какое условие не выполнено\)\.

У работ A → B → C построена цепочка транзитивных ссылок

Пользователь пытается добавить в работу C транзитивную ссылку на A \(или на любую работу из её цепочки\)

Сохранение блокируется; пользователь видит сообщение о цикле с указанием пути\.

30

Фактор члена — только из параметров трудоёмкости работы

У работы открыто добавление фактора в член\-множитель

Пользователь открывает список параметров для фактора

В списке доступны только параметры, добавленные в блок «Параметры трудоёмкости» работы для текущего стрима\. Если их нет — список пуст с подсказкой\.

31

Запрет повтора параметра в одном члене

В члене уже есть фактор по параметру X

Пользователь пытается добавить ещё один фактор по тому же параметру X

Действие отклоняется с сообщением о повторе\. Этот же параметр может быть фактором другого члена\.

__ОКРУГЛЕНИЕ__

32

Изменение режима округления

Карточка работы открыта

Пользователь меняет режим округления

Превью пересчитывается с применением нового режима\. Если выбран режим «без округления» — поле шага становится недоступным\.

33

Отклонение некорректного шага

Режим округления — любой, кроме «без округления»

Пользователь вводит ноль / отрицательное число / нечисловое значение / число вне допустимого диапазона

Сохранение блокируется; пользователь видит сообщение об ошибке валидации\.

__ВЕРСИОНИРОВАНИЕ ШАБЛОНА__

34

Изменение формулы в опубликованной версии шаблона

Работа используется в опубликованной версии шаблона

Пользователь меняет формулу или округление работы

Открывается модалка с предложением создать минорную версию шаблона\. При подтверждении создаётся минорная версия, изменения применяются к ней; опубликованная версия остаётся неизменной\.

35

Активная версия шаблона

У шаблона несколько версий с разными статусами

Пользователь смотрит на список версий

Статусом «Активная» помечена ровно одна версия; именно она используется для новых расчётов анкеты\.

__УДАЛЕНИЕ И КАСКАДЫ__

36

Удаление работы, используемой в опубликованных версиях анкеты

Работа учтена в опубликованных версиях анкеты

Пользователь инициирует удаление работы

Открывается модалка с подтверждением каскадного удаления и информацией о версиях анкеты, где работа учтена\. При подтверждении работа удаляется из справочника; учтённые версии анкеты остаются неизменными\.

37

Удаление работы — источника транзитивной ссылки

На работу указывает транзитивная ссылка из другой работы

Пользователь инициирует удаление работы

Удаление отклоняется; пользователь видит список работ, ссылающихся на удаляемую, чтобы предварительно разрешить ссылки\.

38

Удаление параметра трудоёмкости, используемого как фактор

Параметр используется как фактор хотя бы одного члена формулы

Пользователь инициирует удаление параметра из блока параметров трудоёмкости

Открывается модалка с подтверждением\. При подтверждении параметр и все его факторы в членах формулы помечаются невалидными или удаляются согласно выбору пользователя\.

__КАТАЛОГ, НАЗНАЧЕНИЯ И МОДАЛКА \(новая парадигма\)__

39

Создание работы через модалку — режим создания

Пользователь нажимает «\+ Новая типовая работа»

Заполняет название, выбирает архитектурный компонент, стрим\-исполнитель, задаёт стартовый норматив, нажимает «Создать работу»

В каталог добавляется новая запись; для выбранной комбинации \(арх\. компонент \+ стрим\) создаётся первое назначение работы со стартовой нормой и открытым периодом действия; пользователь перенаправляется на карточку назначения\.

40

Кнопка «Создать работу» недоступна до прохождения валидации

Модалка создания открыта

Хотя бы одно из обязательных полей не заполнено или содержит невалидное значение

Кнопка «Создать работу» недоступна; под некорректным полем — пояснение, что нужно поправить\.

41

Редактирование реестровых полей записи каталога — режим редактирования

Пользователь открывает действие «изменить» на карточке работы

Меняет название и/или архитектурный компонент, нажимает «Сохранить»

Изменения применяются к записи каталога\. Назначения и связанные с ними нормы / условия / параметры / формула не затрагиваются\. Подсказка под формой: «Изменения применяются сразу к справочнику»\.

42

В режиме редактирования не отображаются стрим и стартовый норматив

Пользователь открывает модалку в режиме редактирования

Просматривает форму

Поле «Стартовый норматив, чел\.\-дн\.» скрыто; поле «Стрим\-исполнитель» помечено «\(рекомендация\)» и не сохраняется в запись каталога\.

43

Пустое состояние области

Для выбранной области \(тип арх\. компонента \+ стрим\) нет ни одного назначения

Пользователь открывает экран

В центре отображается информационное сообщение о справочнике и действия «Добавить из каталога» и «\+ Новая типовая работа»\.

44

Добавление работы из каталога в область

В каталоге есть работа, не назначенная на текущую область

Пользователь выбирает её в панели «Добавить из каталога» и подтверждает

Создаётся пустое назначение работы на \(тип арх\. компонента \+ стрим\); пользователь переходит на карточку назначения\. Норма, условия, параметры и формула — пустые / по умолчанию\.

45

Запрет повторного назначения на одну область

У работы уже есть назначение на текущую область

Пользователь открывает панель «Добавить из каталога»

У этой работы действие добавления недоступно с подсказкой «Уже добавлено в эту область»\.

46

Снятие назначения с области

Карточка назначения открыта

Пользователь инициирует действие «снять с этой области» и подтверждает

Удаляются нормы, условия, параметры, члены формулы, факторы только этого назначения\. Запись каталога и другие назначения этой работы остаются нетронутыми\.

__УСЛОВИЯ ТИПА «ОДНО ИЗ ЗНАЧЕНИЙ» \(ANYOF\)__

47

Создание условия типа ∈ \(anyof\)

У назначения открыто добавление условия; выбран параметр

Пользователь выбирает тип условия «∈ \(одно из\)» и отмечает несколько значений в множестве

Условие сохраняется\. UI отображает множество как чипы с отметками; подсказка под полем — «Работа появляется, если ответ — одно из выбранных значений»\.

48

Срабатывание условия anyof

У назначения есть условие типа ∈ с множеством значений \{V1, V2, V3\}

В анкете на параметр выбран ответ V2

Условие выполнено; если других условий нет или они тоже выполнены — работа появляется в анкете и участвует в расчёте\.

49

Условие anyof с пустым множеством отклоняется

У назначения открыто добавление условия; выбран тип ∈ или ∉

Пользователь не выбирает ни одного значения и пытается сохранить

Сохранение блокируется; сообщение: «Выберите хотя бы одно значение в множестве»\.

50

Условие типа ∉ \(none of\)

У назначения есть условие типа ∉ с множеством значений \{V1, V2\}

В анкете на параметр выбран ответ V3 \(не входит в множество\)

Условие выполнено; работа подставляется в анкету \(при выполнении остальных условий\)\.

__ПАРАМЕТРЫ ТРУДОЁМКОСТИ ВИДА ANY\-OF__

51

Переключение параметра на вид «any\-of»

У назначения добавлен параметр трудоёмкости в виде «по значениям»

Пользователь переключает вид на «any\-of» и подтверждает \(если ранее были заданы пользовательские коэффициенты\)

Состав строк коэффициентов перестраивается: вместо словаря «значение → коэффициент» отображаются мультивыбор значений и два числовых поля «on» и «off» \(по умолчанию 1\)\.

52

Применение коэффициента «on» / «off» в расчёте

У назначения параметр трудоёмкости в виде «any\-of» с множеством \{V1, V2\} и коэффициентами on / off

В анкете на параметр выбран ответ V1

В расчёте применяется коэффициент «on»; если бы был выбран V3 \(не в множестве\) — применился бы «off»\.

53

Запрет отрицательных коэффициентов on / off

Карточка коэффициентов any\-of открыта

Пользователь вводит отрицательное число в «on» или «off»

Сохранение блокируется; сообщение об ошибке валидации\.

__ИНТЕГРАЦИОННЫЕ СЦЕНАРИИ__

54

Расчёт работы с множителями и слагаемыми

У работы для стрима задана действующая норма; в формуле есть встроенный член «Базовый норматив работы», член\-множитель и член\-слагаемое со своими факторами

В анкете заданы ответы по параметрам факторов и выполнены все условия

Превью отображает развёрнутый расчёт с подставленными значениями и итог в чел\.\-дн\., полученный по правилам видов членов и применённому округлению\.

55

Расчёт работы с транзитивной ссылкой

У работы формула — транзитивная ссылка на другую работу\-источник; источник имеет валидную формулу и выполненные условия

Выполняется расчёт версии анкеты

Значение работы равно значению работы\-источника\. Норма и параметры трудоёмкости текущей работы в расчёте не участвуют\.

56

Работа исключена из расчёта при отсутствии нормы на дату

У работы для стрима нет действующей записи нормы на дату расчёта анкеты

Выполняется расчёт

В превью отображается ошибка отсутствия действующей нормы; работа исключается из расчёта анкеты \(или итог по ней — прочерк, в зависимости от политики расчёта\)\. На уровне UI это видно в шапке карточки и в превью\.

57

Работа исключена при невыполнении условий

У работы для стрима есть условия

В анкете заданы ответы, при которых хотя бы одно условие не выполняется

Работа не подставляется в анкету; итоговое значение по работе в общей сводке расчёта анкеты равно нулю \(или работы нет в перечне — согласно политике расчёта\)\.
