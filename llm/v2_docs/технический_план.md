# Smart-Анкета v2 — технический план реализации

> Операционный документ для разработки. Предполагаемая модель работы: 1 fullstack + Opus-агент, ритм 12 h/day. Для контекста и бизнес-части см. `зачаток_требований.md`, для глубокой аналитики — `v2_analytycs.md`.
>
> **Принципы:**
> 1. Каждая задача — отдельный PR с зелёным CI, не больше ~300 строк diff.
> 2. Мастер-ветка всегда деплоится. Ни одна правка в R0 не ломает v1-форму.
> 3. Новые зависимости добавляются через `npm install` с актуальной версией, не «вручную пишем в package.json».
> 4. После каждого пункта — прогон `npm run lint` + `npm test` + smoke в браузере.

---

## 0. Инфраструктура работы

### 0.1 Ветвление

- `main` — production.
- `refactor/r0` — зонтичная ветка Итерации 0 (для крупных merge-задач). Мелкие PR-ы идут прямо в `main` при наличии зелёного CI.
- `feat/r1-v2-mvp` — зонтик Итерации 1.
- `feat/r2-admin-constructor` — зонтик Итерации 2.
- Фиче-ветки — от соответствующего зонтика: `refactor/r0-be-2-dto-typos`, `feat/r1-fe-4-risk-matrix` и т.д.

### 0.2 Коммиты и PR

- Формат сообщения (commitlint): `refactor(r0-be-2): fix typos in CreateCalculationDto ValidateIf`.
- PR title = commit title. PR body содержит: Summary (1–3 булита), Test plan (чек-лист из ручной/авто проверки).
- До мерджа: `npm run lint && npm run build && npm test`.

### 0.3 Пакеты

- `packages/anketa-contracts` — новый workspace-пакет, zod-схемы + утилиты + сгенерированные JSON-схемы. Используется и беком, и фронтом (через monorepo).
- `packages/anketa-rules` — маленький пакет для AST-интерпретатора коэффициентов (Итерация 1). Опционально — держать в `anketa-contracts`.

### 0.4 Что НЕ меняем в R0

- Keycloak / permission система.
- Структуру реакт-компонентов верхнего уровня (`AnketaCreatePage`, `AnketaPreviewPage`).
- Контракты v1 — только чинятся опечатки, общий смысл остаётся.
- Миграции v1-данных — **не делаем**. Добавляем новые колонки nullable.

```sql
CREATE TABLE customer (

CREATE TABLE anketa_template (

CREATE INDEX anketa_template_active_idx ON anketa_template(code) WHERE status = 'active';

CREATE TABLE dictionary (
```

- Проверить, что в `rules` и `calc_ruleset` нет циклов (топологическая сортировка AST).

#### R2-BE-4. Audit log

```sql
CREATE TABLE anketa_template_audit (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),

  action text NOT NULL,        -- create|update|publish|archive|clone
  user_email text NOT NULL,
  diff jsonb,
  created_at timestamptz DEFAULT now()
);
```
