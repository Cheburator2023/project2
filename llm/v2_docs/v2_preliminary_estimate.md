# Предварительный анализ создания v2 интерфейса калькулятора

## Контекст
- Основание: обсуждения, стенограмма, CSV с параметрами UX, макеты экранов.
- Четких требований пока нет; есть только концепция первой итерации.
- Оценка ниже относится к **полному объему первой итерации v2** в расчете на `1 strong fullstack developer + мощный AI agent`.
- Целевой горизонт: `1-2 месяца`.

## Главный вывод
- Если считать, что AI agent реально берет на себя значимую часть кодогенерации, рефакторинга, CRUD-обвязки, миграций, тестовых заготовок и рутинной интеграции, то срок можно **существенно ужать без урезания scope**.
- Но AI почти не убирает время на: согласование формул, фиксацию параметров, принятие продуктовых решений, UAT и итерации с бизнесом.
- Поэтому `1-2 месяца` возможно только как **агрессивный план** при хорошем freeze требований и высокой личной скорости разработчика.

## Что входит в полный scope первой итерации
- Новая форма анкеты по макетам.
- Общая информация.
- Детальная информация по ключевым стримам.
- Правая sticky-панель итоговой оценки.
- Подробный расчет в упрощенном виде.
- Живой пересчет коэффициентов на фронте.
- Сохранение/загрузка анкеты.
- Поддержка старой и новой версии шаблона без миграции старых данных.
- Минимальные словари на бэке.
- Предварительный рефакторинг расчетного и schema-слоя.
- Легкая техническая админка для редактирования `jsonschema`, конфигов и справочников.

## Предварительный рефакторинг
Рефакторинг включается в первой поставке в объеме, который напрямую снижает риск:
- унифицировать контракты в **одно место правды**: схема данных, TypeScript-типизация, `jsonschema`, UI-конфиги и версии контрактов должны собираться из единого источника, а не жить разрозненно;
- вынести вычислитель из React-компонентов;
- выделить базовый контракт данных v2;
- развести `schema`, `ui config` и `dictionary data`;
- заложить `schemaVersion/templateVersion`.

## Легкая админка
Это не backoffice, а технический внутренний экран.

Что включать:
- список схем/справочников;
- просмотр и редактирование `jsonschema`;
- редактирование простых справочников;
- редактирование базовых UI-конфигов;
- серверная валидация перед сохранением;
- сохранение новой версии сущности.

Что не включать:
- публикация с workflow;
- история изменений;
- ролевая модель;
- сложные UI-конфиги с визуальным редактором.

## Оценка по трудозатратам

### Вариант full scope + AI acceleration

| Блок | Часы |
|---|---:|
| Уточнение scope и freeze параметров | 24-36 |
| UI-shell, layout, модалки, ключевые секции | 24-34 |
| Движок форм, условная логика, repeatable-блоки | 44-60 |
| Калькулятор, коэффициенты, подробный расчет | 40-52 |
| Backend minimum: шаблоны, словари, save/load, версии | 34-48 |
| Предварительный рефакторинг ядра | 24-36 |
| Легкая админка для `jsonschema`/конфигов/справочников | 40-56 |
| Интеграция, тесты, UAT-фиксы | 36-48 |
| Резерв на уточнение требований | 24-32 |
| **Итого** | **290-402 ч** |

## Вывод по сроку
- Агрессивный сценарий: `290-330 ч`, то есть примерно `1.5-2 месяца`.
- Реалистичный рабочий коридор: `330-370 ч`, то есть примерно `2 месяца`.
- Верхняя граница `402 ч` уже означает, что требования начали плыть и срок уходит выше целевого.

## Декомпозиция по backend/frontend
- Frontend: `180-220 ч`
- Backend: `75-100 ч`
- Аналитика/тесты/буфер: `35-55 ч`

## План по этапам

### Этап 1. Freeze MVP
`0.5-1 неделя / 24-36 ч`
- зафиксировать конечный набор параметров;
- утвердить только baseline-формулы.

### Этап 2. Минимальное ядро
`0.5-1 неделя / 24-36 ч`
- вынести вычислитель;
- оформить версии шаблонов;
- подготовить контракты данных.

### Этап 3. Основной UI калькулятора
`2-3 недели / 110-145 ч`
- layout;
- ключевые секции;
- repeatable-блоки;
- модалки;
- правая панель оценки;
- условная логика.

### Этап 4. Backend minimum
`1-1.5 недели / 34-48 ч`
- save/load;
- словари;
- template/schema version;
- поддержка старой и новой формы.

### Этап 5. Админка lite
`20ч`
- список сущностей;
- текстовый/формовый редактор схем;
- редактирование справочников и базовых UI-конфигов;
- валидация и сохранение версии.

### Этап 6. Стабилизация
`0.5-1 неделя / 36-48 ч`
- регрессия;
- UAT-фиксы;
- косметические UX-правки без редизайна.

## Главные риски
- Формулы и коэффициенты могут меняться уже в процессе.
- AI ускоряет код, но не заменяет продуктовую фиксацию требований.
- Легкая админка легко разрастается в полноценный config-backoffice.
- Если не заморозить формулы и словари в первые 1-2 недели, срок сразу сдвинется.

## Практическая рекомендация
- Если цель именно `1-2 месяца`, проект нужно вести как **агрессивную delivery-итерацию**:
  - быстро freeze требований;
  - много implementation-задач отдавать AI agent;
  - руками добивать формулы, интеграцию и приемку;
  - не расширять админку в продукт.

## Финальная оценка
- **Full scope первой итерации с AI acceleration:** `290-402 ч`
- **Целевой рабочий план:** `330-370 ч`
- **Управленческий вывод:**  
  уложиться в `1-2 месяца` можно без урезания первой итерации, если AI действительно закрывает значимую долю implementation-рутины и требования быстро фиксируются
