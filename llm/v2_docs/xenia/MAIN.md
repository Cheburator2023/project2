**1\. Термины и определения**

| **Термин**                                   | **Определение**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Архитектурный компонент**                  | **Типовой структурный элемент, представляющий отдельную функциональную область:**<br><br>**\- Система-источник - внешние или внутренние источники данных;**<br><br>**\- Объект / Витрина данных - витрины и наборы данных в платформе;**<br><br>**\- Процесс обработки данных - потоки интеграции и преобразования данных;**<br><br>**\- Информационный сервис - аналитический сервис, объединяющий витрины и модели;**<br><br>**\- Модель - обученный артефакт, который по заданному вектору вычисляет значение.**<br><br>**\- Канал внедрения - способ применения результатов модели; Контроль модели - мониторинг и валидация работы модели.**<br><br>**Состав типов компонентов считается фиксированным на текущий момент, однако архитектура системы должна допускать его расширение в будущем без переписывания механики.** |
| **Параметр компонента (= Параметр-триггер)** | **Характеристика архитектурного компонента, которую пользователь задаёт в форме анкеты. Любой параметр компонента при задании его значения одновременно является триггером для поиска связанных типовых задач в справочнике.**<br><br>**Параметры могут быть числовыми (количество источников), логическими (да/нет, например «Источник новый»), или справочными (выбор из списка, например тип контроля).**<br><br>**Состав параметров хранится в отдельном справочнике, расширяем без изменения кода - добавление нового параметра означает появление новой строки в справочнике, а не доработку логики приложения.**                                                                                                                                                                                                           |
| **Типовая задача**                           | **Единица работы, которая жёстко привязана к конкретной связке «Архитектурный компонент + значение его параметра».**<br><br>**Типовые задачи не создаются пользователем вручную - они автоматически подтягиваются системой из справочника, как только пользователь задаёт или изменяет значение параметра компонента.**<br><br>**Каждая типовая задача несёт нормативную (фиксированную) оценку трудоёмкости в человеко-днях, установленную методологом и хранящуюся в справочнике.**<br><br>**Список типовых задач в анкете актуализируется реактивно: при изменении значения параметра задачи, условие которых перестало выполняться, исчезают; новые - появляются.**                                                                                                                                                           |
| **Нетиповая задача**                         | **Единица работы, которая не привязана ни к одному архитектурному компоненту и не имеет нормативной оценки. Нетиповые задачи отражают специфические активности конкретного стрима или проекта - то, что выходит за рамки типового сценария.**<br><br>**Они добавляются пользователем вручную в отдельном разделе анкеты. Пользователь самостоятельно указывает: название задачи, причину (обоснование, почему задача не вписывается в типовое), базовую оценку трудоёмкости в ч/д и коэффициент сложности или риска.**<br><br>**Итоговая оценка задачи вычисляется по формуле: Итог = Оценка × Коэффициент.**<br><br>**Каждая нетиповая задача явно включается или исключается из итоговой сметы через тоггл «Включить в расчёт».**                                                                                               |
| **Справочник типовых задач**                 | **Централизованный реестр правил, связывающих параметры архитектурных компонентов с конкретными работами и их нормативными оценками.**<br><br>**Одна запись справочника описывает правило вида: «Если для компонента типа X задан параметр Y со значением Z - включить в анкету задачу N с оценкой M ч/д». Справочник является ключевым элементом расширяемости системы: добавление нового параметра или новой работы означает добавление строки в справочник, а не изменение кода механики.**                                                                                                                                                                                                                                                                                                                                    |
| **Нормативная оценка**                       | **Фиксированная оценка трудоёмкости в человеко-днях, установленная для типовой задачи и хранящаяся в справочнике типовых задач. Нормативная оценка отражает среднюю трудоёмкость выполнения данной работы при типовых условиях. Пользователь не может изменить нормативную оценку в рамках анкеты - она задаётся методологом при наполнении справочника.**<br><br>**Для нетиповых задач нормативной оценки нет: пользователь указывает произвольную базовую оценку, которая затем умножается на коэффициент.**                                                                                                                                                                                                                                                                                                                    |
| **Коэффициент (нетиповой задачи)**           | **Числовой множитель, применяемый к базовой оценке нетиповой задачи для учёта сложности, неопределённости или рисков.**<br><br>**Итоговая оценка нетиповой задачи = Базовая оценка × Коэффициент. Например, задача с оценкой 12 ч/д и коэффициентом 1.5 даёт итог 18 ч/д.**<br><br>**Диапазон и формат коэффициента (фиксированный список или произвольный ввод) подлежит согласованию с командой.**                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Итоговая калькуляция**                     | **Суммарная оценка трудоёмкости анкеты, рассчитываемая автоматически на основе включённых задач.**<br><br>**Складывается из двух составляющих: суммы нормативных оценок всех типовых задач с флагом «Включить в расчёт» = true, и суммы итоговых оценок (Оценка × Коэффициент) всех нетиповых задач с тем же флагом. Результирующий показатель - Total - используется как основа для планирования ресурсов и согласования объёма работ по стриму или проекту**                                                                                                                                                                                                                                                                                                                                                                    |

**3\. Функциональные требования**

**F-01. Конфигурируемая структура анкеты (степень проработки требований - средняя)**

Состав разделов, компонентов, параметров и условий отображения описывается в конфигурационном файле формата JSON (JSON Schema + UI Schema). Фронтенд строит форму на основе файла без изменений в коде.

- Добавление параметра или компонента = новая запись в конфигурации; изменение кода не требуется.
- Перечень параметров каждого архитектурного компонента хранится в отдельном нормативном справочнике и загружается в форму динамически в соответствии с типом компонента.
- Отображаются только активные элементы (is_active = true).
- Часть разделов типа 3 отображаются по умолчанию, часть - появляется при выборе соответствующего платформенного стрима.
- Изменение конфигурации одного стрима не затрагивает конфигурации других стримов.
- Начальное состояние при первом открытии: разделы типа 1, 2 и 3 заполнены на основе актуальных макетов; пустая форма не показывается.
- Содержимое всех элементов выбора значений (выпадающие списки, группы переключателей, группы флажков) хранится в таблицах на стороне сервера и не фиксируется в программном коде.

_ℹ Итерация 1: конфигурационный файл правится вручную и подкладывается разработчиком. Графический конфигуратор (административный интерфейс) - следующие итерации._

**F-02. Управление параметрами архитектурных компонентов и автоматическое формирование перечня типовых задач (степень проработки требований - средняя)**

При задании или изменении значения параметра система выполняет поиск в справочнике типовых задач по ключу «тип компонента + параметр + значение» и обновляет перечень задач в режиме реального времени:

• задачи, условие которых выполнено, добавляются с нормативной оценкой из справочника;

• задачи, условие которых перестало выполняться, исключаются;

• при удалении компонента все его типовые задачи удаляются.

Пользователь не может добавлять, удалять или редактировать типовые задачи. Нормативная оценка доступна для изменения только методологом через справочник.

Один и тот же тип компонента допускается добавить в анкету несколько раз; каждый экземпляр имеет независимый набор значений параметров и связанных типовых задач (например, два разных источника данных - два экземпляра компонента «Система-источник» с разными значениями параметров и, соответственно, разными наборами типовых задач).

Логика формирования задач и параметры отображения формы хранятся раздельно: структура - в конфигурации, правила расчёта - в справочнике.

**F-03. Автоматическое формирование перечня типовых задач (степень проработки требований - средняя)**

При задании или изменении значения параметра система выполняет поиск в справочнике типовых задач по совокупности трёх условий: тип архитектурного компонента, наименование параметра, значение параметра. Перечень типовых задач обновляется в режиме реального времени:

• задачи, условие включения которых выполнено, добавляются автоматически с нормативной оценкой трудоёмкости из справочника;

• задачи, условие включения которых более не выполняется, исключаются из перечня;

• при удалении параметра из анкеты все связанные с ним типовые задачи удаляются.

Пользователь не имеет возможности самостоятельно добавлять, удалять или редактировать типовые задачи.

Для каждой типовой задачи предусмотрен признак включения в итоговый расчёт: при его отключении задача сохраняется в перечне, но не учитывается при формировании итоговой оценки трудоёмкости.

**F-04. Нетиповые задачи (степень проработки требований - высокая)**

Пользователь вправе добавить неограниченное количество нетиповых задач в специальном разделе анкеты для отражения работ, не охватываемых нормативным справочником. Каждая нетиповая задача включает следующие атрибуты:

- - - Наименование - оба поля являются обязательными; сохранение задачи без заполнения обоснования не допускается.
      - Тип работ -подтягивается из справочника (на основании методологии ПроПро).
      - Базовая оценка трудоёмкости (чел./дн.) и Коэффициент - задаются пользователем вручную; итоговая оценка вычисляется автоматически по формуле «Базовая оценка × Коэффициент» и не доступна для ручного редактирования.
      - Признак включения в итоговый расчёт - управляет участием задачи в итоговой оценке трудоёмкости. Значение по умолчанию подлежит согласованию (см. Q-03).

**F-05. Универсальная логика расчёта трудоёмкости (степень проработки требований - низкая)**

Расчёт итоговой трудоёмкости строится на единой мультипликативной модели без индивидуальных формул для каждого стрима:

- Параметры каждой группы элементов (общие параметры раздела, параметры компонента) образуют локальный коэффициент путём перемножения своих весовых значений.
- Локальные коэффициенты трёх групп (параметры раздела, параметры компонента, задачи) перемножаются между собой - результат является итоговым коэффициентом раздела.
- Итоговая оценка трудоёмкости = нормативная оценка типовой задачи × итоговый коэффициент.

Перемещение параметра в другую группу или компонент изменяет только его место в расчёте, но не требует переписывания формулы - весовой коэффициент параметра следует за ним.

**F-06. Итоговая оценка трудоёмкости (степень проработки требований - средняя)**

Итоговая оценка трудоёмкости по анкете рассчитывается автоматически как сумма нормативных оценок типовых задач и итоговых оценок нетиповых задач, имеющих активный признак включения в расчёт.

Значение пересчитывается при любом изменении состава или параметров задач анкеты.

Формат представления итогового значения (единая сумма либо раздельная детализация по типовым и нетиповым задачам) подлежит согласованию ( ! Согласовать)

**F-07. Версионность (степень проработки требований - средняя)**

Система поддерживает независимое версионирование конфигурационной схемы и данных заполненных анкет.

**Версионирование схемы (конфигурационного файла):**

• Каждое изменение конфигурационного файла фиксируется как новая версия схемы с метаданными: номер версии, дата, автор, краткое описание изменения.

• Мажорная версия (X.0) - изменения, затрагивающие логику расчёта трудоёмкости: состав параметров, весовые коэффициенты, структура зависимостей. Обратная совместимость расчёта не гарантируется.

• Минорная версия (X.1) - изменения, затрагивающие только представление: метки полей, порядок отображения, подсказки, признак активности справочного значения.

• Доступен просмотр любой версии схемы и откат к ней. Откат создаёт новую версию, история не перезаписывается.

• Изменение конфигурации одного стрима не создаёт новую версию схемы других стримов.

**Версионирование данных анкет:**

• Каждая заполненная анкета хранит ссылку на версию схемы, по которой она была создана.

• При открытии анкеты система использует версию схемы, зафиксированную на момент её создания, - изменения в более новых версиях схемы на уже сохранённую анкету не влияют.

• Пересчёт сохранённой анкеты по новой версии схемы выполняется только явным действием пользователя с предупреждением об изменении результата.
