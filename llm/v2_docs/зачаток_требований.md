# Smart-Анкета v2 — зачаток требований

> Источники: обсуждение 2026-04-21 (Шурыгин, Кузьминов, Игнатенко, Максютов, Якупова, Зиновьев, Николаев), макеты Вилена Максютова.

---

## 1. Зачем мы это делаем

Сейчас смарт-анкета решает ровно одну задачу — оценить работы **модельного стрима** (ПиРМ) в проекте по созданию модельного сервиса. Мы хотим превратить её в инструмент, который:

1. Оценивает вклад **всех стримов**, участвующих в создании модельного сервиса: ПиРМ (модель), Источники данных, Контроль моделей, ML-платформа, а дальше — любые новые заказчики-стримы.
2. Отображает **внутреннюю архитектуру** модельного сервиса (системы-источники, объекты данных, процессы обработки, модели, каналы внедрения) и через эти архитектурные компоненты автоматически подключает команды-исполнители.
3. Поддерживает **несколько шаблонов** анкеты одновременно (v1 — живёт до конца 2026, v2 — новые проекты, потенциально персональные шаблоны под заказчика).
4. Даёт админу **редактировать схему анкеты, справочники, коэффициенты** в браузере, без деплоя.
5. Сохраняет ретроспективную точность: открытая старая анкета всегда рендерится **той же версией схемы**, которой её создавали.

## 2. Кто пользователи

| Роль | Что делает в системе |
|---|---|
| **Модельный стрим (лидер)** | Заводит анкету, описывает модельный сервис через архитектурные компоненты, выставляет параметры. |
| **Платформенный стрим (Источники данных, Контроль моделей, ML-платформа)** | Видит, какие его работы автоматически подтянулись по анкете, выставляет локальные параметры, добавляет нетиповые задачи своего стрима. |
| **Заказчик / РП** | Смотрит итоговую оценку, сравнивает версии, экспортирует в Excel. |
| **Администратор** | Редактирует шаблоны анкеты, справочники, коэффициенты, публикует новые версии. |
| **Разработка** | Не трогает код, когда добавляется новый параметр или стрим. |

## 3. Что меняется в анкете v2

### 3.1 Структура разделов

**Было (v1):**
1. Общая информация.
2. Параметры модели.
3. Итоговая оценка.

**Будет (v2):**
1. **Общая информация** — метаданные инициативы + параметры, перенесённые из старого раздела 2 (сложность постановки, каналы внедрения, сроки, стоимость, общая неопределённость).
2. **Детальная информация (модельный стрим)** — архитектурные компоненты модельного сервиса:
   - Системы-источники.
   - Процессы обработки данных.
   - Объекты / витрины данных (источники для обучения + витрины применения).
   - Модели (каскад/ансамбль, тип ML, контур, сценарии).
   - Нетиповые задачи модельного стрима.
3. **Секции платформенных стримов** (каждая — сворачиваемый блок):
   - ML-платформа (стрим ПиРМ-платформа).
   - Контроль моделей.
   - Хранение и обработка данных (источники данных).
   - Каждый платформенный стрим содержит: локальные параметры + автоматически подтянутые типовые задачи + ручные нетиповые задачи.
4. **Итоговая оценка (правый фиксированный блок)**:
   - Базовая оценка по стриму (СФЕРА).
   - Оценка с поправкой на коэффициент сложности.
   - Отклонение от базы по СФЕРА (%).
   - Подробный расчёт по этапам (01–09, 05A, 05B, AML, KPI).
   - Разбивка по стримам (добавляется 4+ строк).

### 3.2 Архитектурные компоненты (ключевая новая концепция)

Модельный стрим описывает свой сервис **через 6–7 архитектурных компонентов**:
- Информационный / модельный сервис (корневой).
- Система-источник.
- Объект / набор данных (витрина).
- Процесс обработки данных.
- Модель.
- Контроль моделей (сущность, а не только стрим).
- Канал внедрения.

Для каждого компонента заводится **набор параметров**. По параметрам **автоматически срабатывают триггеры**, которые подключают типовые задачи платформенных стримов.

Пример: если на модели стоит параметр «Требуется AutoML» → в анкете появляются задачи команды AutoML с оценкой и коэффициентом.

### 3.3 Типы задач

1. **Типовые обязательные** — срабатывают при одном наличии архитектурного компонента (пример: «появился модельный сервис → задача регистрации в СУМ»).
2. **Типовые необязательные** — срабатывают по набору параметров (пример: «AutoML = Да» + «Канал = LLM»).
3. **Нетиповые** — ручные, заполняются в анкете: название, оценка, коэффициент, включить-ли в расчёт.

### 3.4 Общая неопределённость (отдельная фича)

Кнопка «Рассчитать общую неопределённость» открывает модалку (см. макет «Рассчёт общей неопределенности.png») с:
- Сроки инициативы.
- Стоимость инициативы.
- Поправка на общую неопределённость.
- Группа рисков (11 стандартных + N пользовательских).

На выходе — один интегральный коэффициент, влияющий на все этапы.

### 3.5 Версионирование и совместимость

- **Старые анкеты (2026)** — открываются старым рендером, read-only, без миграции данных.
- **Новые анкеты (2027+)** — создаются на v2.
- Каждая анкета записывает, **какой версией шаблона она создана**. При открытии показывается именно та форма.
- Список версий анкеты перерисован: один управляющий компонент, сразу показывает статус и активную версию, позволяет переключаться (см. макет «Список версий.png»).

### 3.6 Шаблон и копия анкеты

Переименование:
- «Создать шаблон» → **«Создать копию анкеты»** (копирует поля в новую анкету).
- Отдельного хранилища шаблонов пока нет — это итерация 2+ (реестр инициатив и шаблонов).

### 3.7 Тёмная тема

Дизайн включает стандартную MUI dark theme (контрастность планируется ослабить). Выгружается через CSS-переменные от дизайнера.

## 4. Что должен уметь администратор

Пока админки нет вообще. Итерация «Админка-конструктор» делает следующее:

- Создать **новый шаблон анкеты** (с нуля или клон существующего). Назначить заказчика.
- Редактировать **структуру секций**: drag-n-drop, названия, порядок, раскрытие по умолчанию.
- Редактировать **поля**: тип (число, селект, шкала, чекбокс, матрица рисков…), обязательность, значение по умолчанию, подсказки, связь со справочником.
- Редактировать **условную логику**: «показать поле Y, если поле X = N», «сделать обязательным при…», без написания кода.
- Редактировать **справочники** (department, streamExecutor, классы моделей, каналы внедрения и т.д.): добавить/удалить/переименовать пункт, указать коэффициент.
- Редактировать **коэффициенты и формулы этапов** через визуальный редактор (никаких `eval`).
- **Предварительный просмотр** — как анкета выглядит для конечного пользователя.
- **Публикация версии**: `draft → active → archived`. Новая активная автоматически архивирует предыдущую.
- **Журнал изменений** (кто, что, когда поменял).
- Нельзя удалить шаблон, если по нему создана хоть одна анкета.

---

## 5. Что получит конечный пользователь (UX-изменения)

1. **Форма разбита на сворачиваемые секции** (Accordion), большинство секций свёрнуто по умолчанию.
2. **Правая панель итоговой оценки прикреплена**, всегда на виду, пересчитывается на лету.
3. **Архитектурные компоненты вводятся как мини-таблицы** внутри секции (строка = источник, строка = модель и т.д.), каждая строка раскрывается модалкой для ввода множества параметров.
4. **Сегментные переключатели** (segmented controls) вместо радио-групп для шкал (сложность, объём по сущностям, детализация).
5. **Бейдж коэффициента** прямо рядом с вариантом выбора: сразу видно, на сколько ×N поднимется/упадёт оценка.
6. **Матрица рисков** с тепловой картой (зелёный → жёлтый → красный).
7. **Инлайн-редактирование названия** анкеты через клик + модалка (вместо отдельной страницы).
8. **Переработанный список версий** — один компонент: badge статуса + выбор версии из dropdown.

## 6. План релизов (high level)

> Дальше — про что мы обещаем **выпустить**, в каком порядке. Точные сроки — в `технический_план.md`. Для пользователя считаем «после разработки ≈ неделя тестирования + QA + обучение».

### Релиз 1 — «v2 MVP + тех-чистка» (июнь-июль 2026)

- Внешне: новая форма анкеты для модельного и (минимально) платформенных стримов; совместимость со старыми записями.
- Внутренне: рефакторинг и переход на data-driven схему; админки ещё нет, шаблоны правятся через миграции/сид.
- Это закрывает: решения 1–4 из обсуждения + п. «двумя версиями шаблонов».

### Релиз 2 — «Админка-конструктор» (август 2026)

- Внешне: админ может через UI создавать новые шаблоны, править справочники и коэффициенты, публиковать версии.
- Внутренне: визуальный редактор, audit log, безопасные формулы.
- Это закрывает: п. «справочники могут меняться в рамках одной версии схемы».

### Релиз 3 — «Реестр инициатив и связи» (осень 2026)

- Реестр всех анкет с выжимкой, связи между анкетами, первый выход из «документного» хранения.
- Это соответствует **итерации 2** из плана Шурыгина.

### Релиз 4 — «Полноценная архитектура сервисов» (конец 2026)

- Визуальный редактор архитектурных компонентов (drag-n-drop, как DataLineage).
- Полноценные справочники архитектурных компонентов.
- Нетиповые работы как отдельный тип анкеты.
- Связи архитектурных компонентов между анкетами (чтобы витрина одного сервиса могла быть потреблена другим).
- Это соответствует **итерации 3** из плана Шурыгина.

### Релиз 5 — «Связь с РФДИ и этапами работ» (2027)

- Один модельный сервис может реализовываться в нескольких проектах / РФДИ.
- Это соответствует **итерации 4** из плана Шурыгина.

### Релиз 6 — «Гибкий калькулятор» (2027)

- Режим «поиграться»: пользователь прогоняет несколько сценариев, сохраняет понравившийся как основной.
- Это соответствует **итерации 5** из плана Шурыгина.

## 10. Словарь терминов

| Термин | Что это |
|---|---|
| **Смарт-анкета** | Web-форма + калькулятор оценки трудозатрат по проекту создания модельного сервиса. |
| **Модельный сервис (МС)** | Корневой объект проекта: модель (или каскад моделей) + витрины + каналы внедрения. |
| **Стрим** | Команда-исполнитель. Бывают: модельный (ПиРМ), платформенные (ML-платформа, Контроль моделей, Источники данных), поддерживающие. |
| **Архитектурный компонент** | Часть модельного сервиса: Система-источник, Процесс обработки, Объект данных, Модель, Контроль, Канал внедрения. |
| **Типовая задача** | Задача, которая автоматически подтягивается в анкету по наличию архитектурного компонента (+ параметров). |
| **Нетиповая задача** | Ручная задача, добавленная пользователем в анкету (с оценкой и коэффициентом). |
| **Коэффициент сложности** | Множитель к базовой оценке этапа (×1.0, ×1.25 …). Зависит от значений параметров. |
| **Общая неопределённость** | Интегральный коэффициент, считается по матрице рисков × сроки × стоимость инициативы. |
| **Шаблон анкеты (anketa_template)** | Описание формы анкеты: JSON-структура полей + правила + коэффициенты. Версионируется. |
| **Справочник (dictionary)** | Список допустимых значений (department, класс модели, канал внедрения…). Правится админом. |
| **СФЕРА** | Базовая оценка (нормативная), по которой рассчитывается план. |
